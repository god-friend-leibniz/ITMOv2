## Воспроизведение

Используется существующий сервер на порту 11435. Для отдельного запуска:

```bash
OLLAMA_HOST=127.0.0.1:11435 OLLAMA_CONTEXT_LENGTH=65536 OLLAMA_NO_CLOUD=1 ollama serve
```

Не запускать второй сервер на занятом порту. В проведённых экспериментах
действующий сервер не перезапускался; его `OLLAMA_NO_CLOUD` не изменялся.
Использовались только скачанные локальные профили, без cloud-тегов.

Из `practices/practice_03/lab/`:

```bash
python3 run_practice.py prepare --results results/new-run
python3 run_practice.py api --results results/new-run
python3 run_practice.py agent --results results/new-run --agent-attempt agent-corrected
python3 run_practice.py explain --results results/new-run
python3 run_practice.py validate --results results/new-run
```

`new-run` должен быть новым каталогом: результаты записываются в режиме `x`
без перезаписи предыдущих файлов. Замеры выполняются последовательно.
`prepare` выполняет `make install`, `make test`, `ollama create` для обоих
профилей и первый локальный запрос. `FROM` в обоих Modelfile уже соответствует
выбранной `qwen3.5:4b`, поэтому менять его не требовалось.

`experiment.py` использует `127.0.0.1:11435/api/chat`. API-сравнения выполняются
на базовой `qwen3.5:4b`, чтобы встроенный SYSTEM профиля `itmo-local` не стал
скрытым дополнительным фактором.

`demo/opencode.json` оставлен неизменным, включая его исходный порт 11434.
Для тестовых процессов адрес 11435 и ограничения передаются через
`OPENCODE_CONFIG_CONTENT`, который имеет более высокий приоритет.
См. [документацию OpenCode](https://opencode.ai/docs/config/).

В корректном агентном запуске разрешён только `read` четырёх входных файлов:
`README.md`, `Makefile`, `service.py`, `test_service.py`. Другие инструменты,
внешние пути, отчёт и результаты запрещены. В runtime-инструкцию добавлен
список доступных файлов, поскольку поиск запрещён. В OpenCode разрешён только
провайдер `ollama`; `--pure`, отключённые обновления и sharing, отсутствие
MCP и внешних плагинов проверены в
[opencode-effective.json](lab/results/run-2026-10-05/agent-corrected/opencode-effective.json).
Это ограничения инструментов OpenCode, а не файловая изоляция всего процесса ОС.

Эталоны подготовлены отдельно в
[reference-answers.md](lab/results/run-2026-10-05/reference-answers.md)
и не передавались тестируемой модели. Каждый из шести запусков OpenCode имеет
свой session ID; продолжение сессии не использовалось. Сохранены текст ответа,
события инструментов и метрики; события внутренних рассуждений исключены.

скорость генерации близка, преимущественно уменьшилась длина ответа.

## Ошибки настройки и ограничения

Первая серия агентных запусков (файлы `questionN` в корне каталога результатов)
не засчитывается как основная проверка: относительные разрешения задавались
от `demo`, а OpenCode проверял их относительно корня Git-репозитория.
Это ошибка рабочего агента, не доказательство неспособности Qwen читать файлы.
Кроме того, при объединении конфигов сохранились исходные разрешения grep/glob;
в первой серии зарегистрирован выполненный grep. В исправленной серии эти
инструменты явно запрещены, а пути разрешений заданы точно от корня репозитория.
Старые ответы сохранены, а не заменены вымышленными успешными результатами.

После исправления обнаружены уже ошибки модели: пропуск нужных источников
в вопросе о тестах; ложное заявление об успешном чтении при отказе инструмента
в вопросе unsubscribe; неполная проверка CI; незавершённое намерение прочитать
Makefile в последнем ответе. Проверка ошибок основана на коде и событиях `read`,
а не только на самоописании модели.

Подготовительный запрос про модель и сервер также показал неоднозначность:
Qwen описала модель как абстрактное представление, а сервер как физический
компьютер, упустив контекст локальной LLM. В нужном контексте модель — веса
нейросети, а `ollama serve` — программный сервис, который загружает веса и
обрабатывает запросы. Следует явно обозначать предмет вопроса.

## FROM, PARAMETER, SYSTEM и инструкции агента

- `FROM qwen3.5:4b` выбирает базовые веса для профиля.
- `PARAMETER` задаёт параметры, например контекст и temperature; API-запрос
  может переопределить параметры профиля.
- `SYSTEM` задаёт системное сообщение профиля Ollama. Оно влияет на ответы,
  но не вводит технические ограничения доступа к файлам.
- Инструкции OpenCode описывают поведение помощника при работе с репозиторием.
  Его `permission` определяет доступность и разрешения инструментов. Поэтому
  запрет shell или чужих файлов должен задаваться правами, а не только текстом.

Отдельный запрос объяснения также выполнен через OpenCode Build без инструментов;
его фактический ответ находится в
[modelfile-explanation.json](lab/results/run-2026-10-05/modelfile-explanation.json).
Этот ответ тоже требует проверки: Qwen ошибочно назвала Modelfile «форматом
MoE модельных файлов» и связала низкую temperature с гарантированной точностью.
Modelfile описывает конфигурацию профиля, а низкая temperature меняет выбор
токенов и не гарантирует правильность. Формулировка про SYSTEM «один раз»
также неточна: это инструкция, используемая при формировании входа модели,
а не одноразовое обучение или изменение весов. Приведённое выше объяснение
рабочего агента исправляет эти ошибки и отделяет текстовые инструкции от
технических прав. Источник: [Modelfile Ollama](https://docs.ollama.com/modelfile).

не разных моделей, компьютеров или квантизаций. В практической части A/B
обозначали отдельное API-сравнение baseline / `lab/system.txt`; здесь prompts
другие и сохранены в `homework/system-a.txt` и `homework/system-b.txt`.

- **A** — краткая роль, требование сначала читать файлы, список разрешённых
  входов, отделение данных проекта от инструкций: [system-a.txt](homework/system-a.txt).
- **B** — тот же текст плюс требование проверяемых file:line, проверки
  предпосылок, запрет домысливать HTTP-статус/SLA/инфраструктуру, различение
  отказа инструмента и успешного чтения: [system-b.txt](homework/system-b.txt).

Веса, квантизация, вопросы, доступные файлы, окно контекста, лимит ответа,
режим рассуждения и остальные настройки одинаковые. Сравнение конфигов
после исключения поля prompt даёт равенство:
[A](homework/results/run-2026-10-05/config-a.json),
[B](homework/results/run-2026-10-05/config-b.json).
Сохранены также эффективные конфиги `effective-*.json` и разрешённые
инструменты `agent-*.json`, а не только исходная декларация.

Разрешён только read ровно шести файлов: корневого Makefile, Makefile практик
1 и 2, `practices/practice_01/TRAINING_PR.diff`, `context.md`, `adr.md`.
Эталоны, отчёт и результаты модели недоступны. Bash, glob, grep, правки,
сеть, делегирование и остальные инструменты запрещены. MCP/плагины/LSP/
форматтер/автообновление/снимки выключены; enabled_providers содержит только
Ollama. У каждой сессии явный title, запуск с `--pure` из корня проекта.

Это изоляция доступных модели инструментов, не системный sandbox всего
процесса Ollama/OpenCode. Хеши файлов до/после подтверждают неизменность
входов. Разные фактически прочитанные подмножества шести файлов — результат
поведения моделей при одинаковом разрешённом наборе, а не изменение фактора.
Context Pack содержит хорошие/плохие примеры предыдущей практики; это
одинаковый доступный материал обеих веток, не независимый экзамен без примеров.

### Ошибка, границы возможностей и выбранная конфигурация

Показательная ошибка A-q3: ответ «В файле practices/practice_01/adr.md»
противоречит смыслу документа и не подкреплён его чтением. Модель прочитала
только Context Pack и diff. Проверяемый эталон требует ADR :3, :15 и :32:
статус proposed, синхронное решение и отвергнутая очередь. Read-only защищает
файлы от изменений, но не защищает ответ от галлюцинации.

B-q3 показывает отдельную границу: код завершения 0 не гарантирует ответа.
В журнале есть step_start/step_finish(reason=stop), 213 output tokens, но
нет text и tool_use. Причина по этим событиям не установлена; считать это
правильным отказом от ложной предпосылки нельзя.

Итоговый ответ B-q3 получен и разобран в таблице. Он не выдумывает настройку
Redis, но пропускает предложенное синхронное решение и содержит ошибки
ссылок. Наличие текста не устраняет содержательные ограничения модели.

Для **ограниченного локального черновика оставляем A**: на данном наборе
больше правильных основных ответов, корректнее q5, нет пустого основного
результата и ниже медиана задержки. Усиленный B не обеспечил требуемые
ссылки. Это малый набор с одним seed, а не доказанное универсальное
преимущество A. Рабочий корневой opencode.json не переписывался ради выбора
экспериментального read-only агента; конфигурация A сохранена отдельно.

### Воспроизведение

Команды запуска, список входов и индекс материалов:
[homework/README.md](homework/README.md).
Автоматизация: [run_homework.py](homework/run_homework.py), использующая
стандартную библиотеку Python; отдельный новый каталог результатов обязателен.
Инструкции запуска требовались HOMEWORK.md явно. В README приведены команды
прогона; в каждом JSON сохранена реальная CLI-команда
в `command`, а конфиг передавался через `OPENCODE_CONFIG_CONTENT` из корня
репозитория.
Проверка: [validation.json](homework/results/run-2026-10-05/validation.json).
Она проверяет свежие сессии, фактический read, whitelist, одинаковые входы,
отсутствие reasoning-событий и неизменность старого отчёта; она не выдаёт
ошибочным ответам модели семантический зачёт. `make test` проверяет артефакты
практик 1–2 и три unittest demo практики 3, не качество ответов Qwen.
