# Домашняя работа: помощник по проекту практик 1–2

Проверяется наш учебный помощник ревьюера PR: контракт и код в
`practices/practice_01/TRAINING_PR.diff`, Context Pack, proposed-ADR и проверки
артефактов практик 1–2. Это не сервис подписок из `lab/demo` и не утверждение,
что полный HTTP-сервис уже реализован в этом репозитории.

## Что означают A и B

Это два варианта **инструкции одной и той же модели**, а не разные модели
или компьютеры. A использует краткий system/agent prompt: отвечать по-русски,
сначала читать нужные файлы, воспринимать документы как данные. B содержит
тот же текст и дополнительные требования: проверять предпосылку вопроса,
не домысливать отсутствующие сведения и подтверждать утверждения file:line
на реально прочитанные файлы. Тексты сохранены полностью в `system-a.txt`
и `system-b.txt`; OpenCode получает их в `agent.homework.prompt`.

В практической части обозначения A/B относятся к отдельному API-эксперименту
без system prompt / с `lab/system.txt`. Это другое сравнение, не те prompts,
которые используются в домашней работе.

## Воспроизведение

Из корня репозитория; нужны Ollama, OpenCode и Python 3. Веса уже скачаны.
Используется тот же endpoint `127.0.0.1:11435`, что и в практической части.
Если сервер не запущен, в отдельном терминале:

```sh
OLLAMA_HOST=127.0.0.1:11435 ollama serve
```

Создать профиль без Ollama SYSTEM (system prompt задаёт OpenCode):

```sh
OLLAMA_HOST=127.0.0.1:11435 ollama create itmo-agent -f practices/practice_03/lab/Modelfile.agent
```

Повторный прогон сохраняйте в **новый** каталог, не поверх сданных результатов:

```sh
python3 practices/practice_03/homework/run_homework.py prepare --results practices/practice_03/homework/results/new-run
python3 practices/practice_03/homework/run_homework.py run --results practices/practice_03/homework/results/new-run
python3 practices/practice_03/homework/run_homework.py validate --results practices/practice_03/homework/results/new-run
```

Скрипт использует только стандартную библиотеку Python. Сохраняет конфиги,
проверяет эффективные разрешения, запускает десять свежих сессий в порядке
A-q1, B-q1, …, A-q5, B-q5, затем шесть свежих сессий для скорости. Не меняет
источники и REPORT.md. Файлы результатов создаются эксклюзивно: повторный
запуск в тот же каталог остановится, а не перезапишет эксперимент.

Для ручного запуска одного вопроса из корня (подставить дословный вопрос):

```sh
OPENCODE_CONFIG_CONTENT="$(<practices/practice_03/homework/results/run-2026-10-05/config-a.json)" opencode run --pure --agent homework --model ollama/itmo-agent --title manual-a --format json 'ВОПРОС'
```

Нельзя добавлять `--continue`/ID прежней сессии, менять prompt между вопросами
или передавать эталон в запрос. Снимки digest в `environment.json` позволяют
заметить обновление весов под прежним тегом.

Описывать запуск требовалось: HOMEWORK.md требует конфиги, инструкции запуска,
оба system prompt, свежую сессию для каждого вопроса, события инструментов и
три прогретых повторения. Фактическая CLI-команда каждого запуска сохранена
в поле `command` его JSON; `session_ids` подтверждает отдельную сессию.
Конфиг передавался через `OPENCODE_CONFIG_CONTENT`, рабочий каталог — корень
этого репозитория. Первичный запуск выполнен командой:

```sh
python3 practices/practice_03/homework/run_homework.py run --results practices/practice_03/homework/results/run-2026-10-05
```

## Одинаковые условия и границы изоляции

Обе ветки: `itmo-agent` на весах `qwen3.5:4b`, Q4_K_M, `num_ctx=65536`,
лимит ответа 2048, `think=false`, seed 42, temperature 0.2, до восьми шагов.
Базовые `top_k=20`, `top_p=0.95`, `presence_penalty=1.5` наследуются от модели.
Эффективные конфиги и инструменты сохранены в `effective-*.json` и
`agent-*.json`. Все провайдеры кроме Ollama отключены; MCP, плагины, снимки,
автообновление, LSP и форматтер отключены. `--pure` и явный `--title` сокращают
посторонние действия запуска.

Единственный доступный инструмент — read. Разрешены ровно:

1. `Makefile`
2. `practices/practice_01/Makefile`
3. `practices/practice_02/Makefile`
4. `practices/practice_01/TRAINING_PR.diff`
5. `practices/practice_01/context.md`
6. `practices/practice_01/adr.md`

Пути permission относятся к корню git-проекта. Эталоны, вопросы как файл,
отчёт, результаты, shell, поиск, сеть, правки и делегирование модели запрещены.
Текст вопроса, конечно, передаётся пользователем в каждый запуск. Контекстный
документ содержит правила старого сценария: в новых prompts он явно объявлен
данными, а не инструкциями агента. Известные примеры в Context Pack входят в
одинаковый набор входов A/B; это не независимый экзамен знаний Python.

Это контроль инструментов OpenCode, **не** системная изоляция процесса Ollama
или OpenCode от всего компьютера. У локальной модели нет самостоятельного
доступа к файловой системе; проверяются предложенные ей инструменты и их
фактические события. Источники разрешены одинаковые, но число прочитанных
файлов может различаться — это наблюдаемый результат поведения агента.

Скорость — медиана трёх **прогретых end-to-end запусков OpenCode** на q1,
в секундах. Перед каждым повтором — короткий `/api/chat` warmup той же модели
с тем же контекстом. Время включает CLI, prompt processing, read и генерацию;
это не TTFT и не токены/с чистого декодирования. Короткие warmup-запросы не
смешиваются с измеренными запусками. Модель/сервер не выгружались специально.
