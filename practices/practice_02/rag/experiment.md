Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Вопрос к источникам: какие утверждения в «Первом рабочем сценарии» и Use case `product_management.md` подтверждены Context Pack и diff, а какие требуют отдельного решения?

## Запрос

Использован раздел «RAG» из [prompts.md](../prompts.md): подготовить доказательный вариант «Первого рабочего сценария» и Use case, снабжая технические утверждения ссылками на разрешённые источники и отделяя неподтверждённое.

## Ответ со ссылками на источники

Предлагаемый вариант «Первого рабочего сценария»:

> Когда инженер отправляет `POST /api/reviews` [источник: `TRAINING_PR.diff`, `@app.post("/api/reviews")`] с JSON, содержащим `diff` [источник: `TRAINING_PR.diff`, `return review_service.review(payload["diff"])`], система формирует prompt из diff [источник: `TRAINING_PR.diff`, `prompt = f"Review this pull request and find problems:\n{diff}"`], вызывает LLM [источник: `TRAINING_PR.diff`, `answer = self.llm.generate(prompt)`] и возвращает `comment` [источник: `TRAINING_PR.diff`, `return {"comment": answer}`]. Человек самостоятельно принимает решение по PR [источник: `context.md`, «Человек принимает решения»].

Предлагаемый Use case:

| Поле | Вариант с источником |
|---|---|
| Актор | Инженер-ревьюер [источник: `product_management.md`, Use case]. |
| Триггер | Отправка `POST /api/reviews` с `{"diff": "<строковый diff PR>"}` [источник: `TRAINING_PR.diff`, endpoint и `payload["diff"]`]. |
| Предусловия | Diff передаётся в сервис как аргумент `diff: str` [источник: `TRAINING_PR.diff`, `def review(self, diff: str)`]. Это не доказывает валидацию HTTP-входа. |
| Основной результат | Сервис возвращает словарь с `comment` [источник: `TRAINING_PR.diff`, `return {"comment": answer}`]; инженер принимает решение по PR [источник: `context.md`, «Человек принимает решения»]. |
| Ошибка или отказ | При отсутствии `diff` видно прямое обращение `payload["diff"]` [источник: `TRAINING_PR.diff`]. Контракт HTTP-ответа не указан в разрешённых источниках. |

Исключённые неподтверждённые утверждения:

- сервис возвращает контролируемую диагностируемую ошибку без `comment`;
- определены HTTP-статус и схема тела ошибки;
- API гарантирует строковый тип `diff` на входе;
- заданы ограничения размера или содержания `diff` и гарантии содержания `comment`.

## Что изменили в исходном артефакте

- Файл и раздел: [`product_management.md`](../../practice_01/product_management.md), «Первый рабочий сценарий» и «Use case».
- Изменение: исходный артефакт не изменялся; доказательный вариант сохранён в разделе «Ответ со ссылками на источники».
- Как проверили ссылки: каждый технический тезис сопоставлен с уникальным фрагментом diff или Context Pack; ссылки на текущий артефакт используются только для уже согласованных границ сценария.
- Что отклонили как неподтверждённое: контракт ошибки, HTTP-статусы, валидацию HTTP-входа, ограничения diff и гарантии содержимого ответа.
