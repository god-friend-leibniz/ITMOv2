# R.C.T.F.

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- **Role:** product analyst, уточняющий критерии приёмки первого сценария AI-помощника для review pull request.
- **Context:** разрешены `context.md`, `TRAINING_PR.diff` и `product_management.md`; инженер выполняет review вручную AS IS, сервис помогает получить черновик, решение по PR остаётся за инженером. Поведение HTTP-обработчиков и реальной LLM не задано.
- **Task:** предложить минимальную правку раздела «User stories и acceptance criteria», сохранив позитивный, негативный и граничный сценарии без новых продуктовых возможностей.
- **Format:** наблюдения о текущем разделе, предлагаемый Gherkin и неизвестное; без изменения файлов.

## Полный запрос

Использован раздел «R.C.T.F.» из [prompts.md](../prompts.md).

## Что получили

Наблюдения агента:

- позитивный сценарий связывает строковый `diff` и поле `comment`;
- контракт ошибки для отсутствующего `diff` не определён источниками;
- граничный сценарий пустого `diff` отсутствует;
- не заданы форма тела ошибки, ограничения на размер diff и гарантии содержимого `comment`.

Предложенный Gherkin:

```gherkin
Feature: Получение черновика ревью по diff
  Как инженер-ревьюер
  Я хочу отправить diff PR сервису и получить черновик комментария от LLM
  Чтобы быстрее начать ревью, оставаясь финальным решающим лицом

  Scenario: Позитивный — валидный diff передан
    Given доступен HTTP-сервис с endpoint /api/reviews
    And у меня есть строка diff PR
    When я отправляю POST /api/reviews с JSON {"diff": "<строковый diff>"}
    Then в ответе возвращается JSON, содержащий ключ "comment" со строковым значением
    And я могу просмотреть этот черновик и принять решение по PR вручную

  Scenario: Негативный — нет ключа "diff" во входе
    Given доступен HTTP-сервис с endpoint /api/reviews
    And я отправляю JSON без ключа "diff", например {}
    When я выполняю POST /api/reviews
    Then ответ не соответствует формату успешного ответа {"comment": "<строка>"}
    And факт несоответствия зафиксирован, тело ответа и заголовки сохранены

  Scenario: Граничный — передан пустой diff
    Given доступен HTTP-сервис с endpoint /api/reviews
    And у меня есть пустая строка diff ""
    When я отправляю POST /api/reviews с JSON {"diff": ""}
    Then в ответе возвращается JSON, содержащий ключ "comment" со строковым значением
    And я могу просмотреть этот черновик и принять решение по PR вручную
```

## Что изменили в исходном артефакте

- Файл и раздел: [`product_management.md`](../../practice_01/product_management.md), «User stories и acceptance criteria».
- Изменение: исходный артефакт не изменялся; вариант RCTF сохранён в разделе «Что получили».
- Как проверили: результат сопоставлен с `context.md` и diff; проверены границы известных фактов.
- Что отклонили: негативный `Then` о несоответствии формату успешного ответа — тело HTTP-ответа после исключения не следует из diff. Граничный `Then` с `comment` для пустого diff — зависит от LLM и становится проверяемым только с заданной заглушкой. Утверждение о контролируемой ошибке в текущем артефакте — неактуально после отката Tree of Thoughts.
