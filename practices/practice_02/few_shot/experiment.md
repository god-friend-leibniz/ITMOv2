# Few-shot

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Артефакт Практики 1: [`product_management.md`](../../practice_01/product_management.md), разделы «Первый рабочий сценарий» и «User stories и acceptance criteria».
- Что хотим улучшить: сделать критерии приёмки наблюдаемыми, сохранив финальное решение по PR за инженером и не назначая HTTP-статусы или внешние интеграции.

## Примеры

### Хороший результат

`When` отправляется `POST /api/reviews` с JSON, содержащим строковый diff,
`Then` ответ содержит строковое поле `comment`, возвращённое LLM-зависимостью;
инженер проверяет черновик и сам принимает решение по PR.

### Плохой результат

`API` всегда возвращает `422`, быстро обрабатывает большие PR и автоматически
отправляет комментарий в GitHub.

Плохой пример назначает неизвестный HTTP-статус, требования к производительности
и несуществующую интеграцию.

## Запрос

Использован раздел «Few-shot» из [prompts.md](../prompts.md): на основе хорошего и плохого примеров
предложить новый текст рабочего сценария и три acceptance criteria без изменения
исходного файла.

## Что получили

Агент предложил сохранить позитивный путь: `POST /api/reviews` получает строковый
diff, сервис запрашивает LLM, возвращает `comment`, а инженер принимает решение
по PR вручную.

Предложенный негативный сценарий:

```gherkin
Scenario: Негативный — отсутствует ключ "diff"
  Given доступен HTTP-сервис с endpoint /api/reviews
  And я отправляю JSON без ключа "diff", например {}
  When я выполняю POST /api/reviews
  Then фиксируется фактический ответ сервиса без назначения статуса
  And успешный формат ответа с ключом "comment" отсутствует
  And тело ответа сохраняется для анализа
```

Предложенный граничный сценарий:

```gherkin
Scenario: Граничный — передан пустой diff
  Given доступен HTTP-сервис с endpoint /api/reviews
  And у меня есть пустая строка diff ""
  When я отправляю POST /api/reviews с JSON {"diff": ""}
  Then в ответе возвращается JSON, содержащий ключ "comment" со строковым значением
  And инженер просматривает черновик и принимает решение по PR вручную
```

## Что изменили в исходном артефакте

- Файл и раздел: [`product_management.md`](../../practice_01/product_management.md), «Первый рабочий сценарий» и «User stories и acceptance criteria».
- Изменение: исходный артефакт не изменялся; few-shot вариант сохранён в разделе «Что получили».
- Как проверили: позитивный сценарий соответствует diff и Context Pack; в нём сохранена роль человека как финального принимающего решение.
- Что отклонили: негативный критерий об отсутствии успешного формата не доказан diff, поскольку внешний обработчик может сформировать другое тело ответа. Граничный критерий с `comment` для пустого diff зависит от поведения LLM и требует детерминированной заглушки. Поэтому вариант не переносится в исходный артефакт.
