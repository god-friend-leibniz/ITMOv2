# Chain of Verification

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Проверяемый черновик или утверждение: раздел «User stories и acceptance criteria» файла [`product_management.md`](../../practice_01/product_management.md), особенно негативный сценарий без `diff`.

## Запрос на проверку

Использован раздел «Chain of Verification» из [prompts.md](../prompts.md): сформулировать не более пяти вопросов к текущему разделу, указать источники и результаты проверки, затем предложить исправленный Gherkin без изменения файлов.

| Остаётся ли решение по PR за человеком? | [`product_management.md`](../../practice_01/product_management.md), позитивный сценарий; [`context.md`](../../practice_01/context.md), «Человек принимает решения». | Да, решение явно остаётся за инженером. |

| Есть ли отдельный граничный сценарий? | `product_management.md`, раздел Gherkin. | Нет, граничный сценарий отсутствует. |

## Исправленный результат

Фактический предложенный агентом негативный сценарий:

```gherkin
Scenario: Негативный — нет ключа "diff" во входе
  Given доступен HTTP-сервис с endpoint /api/reviews
  And я отправляю JSON без ключа "diff", например {}
  When я выполняю POST /api/reviews
  Then ответ не соответствует успешному формату {"comment": "<строка>"}
```

Этот вариант не принят: внешний обработчик может вернуть тело, совпадающее или
не совпадающее с успешным форматом, и diff этого не определяет. Кроме того,
агент обнаружил отсутствие граничного сценария, но не добавил проверяемого
варианта без предположений о LLM.
