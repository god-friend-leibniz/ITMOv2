# ReAct

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Цель: подготовить минимальный проверяемый вариант правки `product_management.md` для первого сценария AI-помощника ревьюера.
- Доступные входы: [`context.md`](../../practice_01/context.md), [`TRAINING_PR.diff`](../../practice_01/TRAINING_PR.diff), [`product_management.md`](../../practice_01/product_management.md).
- Разрешённые действия: прочитать три входа; найти утверждения без источника или ненаблюдаемые acceptance criteria; сопоставить их с Context Pack и diff; предложить правку трёх разделов.
- Запрещённые действия: читать другие файлы, изменять файлы, выполнять HTTP-запросы, додумывать статусы HTTP, интеграции, SLA, пользователей или поведение LLM.
- Максимальное число шагов: 5.
- Условие остановки и вопроса человеку: остановиться после подготовки правки; если нужен неизвестный контракт, задать один вопрос человеку вместо предположения.

## Запрос

Использован раздел «ReAct» из [prompts.md](../prompts.md).

## Фактический результат агента

Предложенный агентом вариант для `product_management.md`:

| Поле Use case | Предлагаемый текст |
|---|---|
| Ошибка или отказ | Поведение при отсутствии ключа `diff` в запросе не определено в рамках этого сценария и должно быть согласовано отдельно; проверка фиксирует фактический ответ без предположений о статусе и схеме. |

```gherkin
Scenario: Негативный — нет ключа "diff" во входе
  Given доступен HTTP-сервис с endpoint /api/reviews
  And я отправляю JSON без ключа "diff", например {}
  When я выполняю POST /api/reviews
  Then я фиксирую фактический ответ сервиса без предположений о статусе и схеме
  And если ответ сформирован, он может не содержать ключ "comment"
```

Вопрос агента человеку: какой контракт ожидается при отсутствии `diff` —
контролируемая ошибка и какая её форма? Этот вариант сохранён как результат
эксперимента, но не применён к исходному артефакту.

## Наблюдаемые действия и результаты

| Шаг | Действие | Наблюдение | Решение продолжить или остановиться |
|---|---|---|---|
| 1 | Прочитать `context.md` | Context Pack запрещает утверждать конкретные HTTP-статусы и неизвестное поведение ошибок. | Продолжить: исключить неподтверждённые обещания о форме ошибки. |
| 2 | Прочитать `TRAINING_PR.diff` | Видны `POST /api/reviews`, прямой доступ `payload["diff"]`, вызов LLM и возврат `{"comment": answer}`. | Продолжить: позитивный сценарий подтверждён, поведение ошибки HTTP-слоя не определено. |
| 3 | Прочитать `product_management.md` | Негативный сценарий описывает ошибочный вход; допустимы разные варианты его продуктовой трактовки. | Продолжить: сформировать минимальную альтернативу без контракта ошибки. |
| 4 | Сопоставить источники | Без дополнительного решения нельзя вывести контролируемую ошибку, HTTP-статус или схему её тела. | Продолжить: сохранить вариант как черновик и задать вопрос человеку. |
| 5 | Подготовить минимальные правки | Предложено оставить позитивный сценарий, а для отсутствующего `diff` фиксировать фактический ответ без предположений о статусе и схеме. | Остановиться: контракт ошибки требует решения человека. |

## Что изменили в исходном артефакте

- Файл и раздел: [`product_management.md`](../../practice_01/product_management.md), «Use case» и «User stories и acceptance criteria».
- Изменение: исходный артефакт не изменялся; вариант ReAct сохранён в разделе «Фактический результат агента» этого файла.
- Как проверили: черновик использует только разрешённые источники, содержит пять наблюдаемых действий и не назначает HTTP-статус.
- Что отклонили: применение варианта к исходному артефакту. Он не учитывает сохранённый в Tree of Thoughts кандидат B и не имеет решения человека по контракту ошибки.
