# Spec Delta

## Purpose

Позволяет студенту видеть оставшуюся работу в выбранном курсе через фильтр заданий по завершённости чек-листа и сохранять выбор при навигации без изменения данных или контрактов JSON API.

## ADDED Requirements

### Requirement: Course-scoped assignment list with compatible defaults

Страница курса SHALL по умолчанию показывать все задания только этого курса в порядке возрастания ID. Фильтрация SHALL затрагивать только HTML-представление списка и SHALL сохранять прежнее поведение JSON API и отсутствующих ресурсов.

#### Scenario: Opening a course without a filter
- **GIVEN** в курсе A есть задания с разными состояниями чек-листа, а в курсе B есть другие задания
- **WHEN** студент открывает страницу курса A без фильтра
- **THEN** выбран режим «Все», показаны все задания A в порядке возрастания ID и ни одного задания B

#### Scenario: JSON list remains unfiltered
- **GIVEN** на странице курса выбран режим «Завершённые»
- **WHEN** клиент запрашивает `GET /api/courses/{course_id}/assignments`
- **THEN** возвращаются все задания этого курса в прежнем порядке и с прежним составом полей, включая прогресс и ссылку на репозиторий
- **AND** параметр фильтра не становится частью контракта JSON API

#### Scenario: Missing course remains a not-found page
- **WHEN** студент открывает страницу несуществующего курса с любым допустимым режимом
- **THEN** возвращается прежняя читаемая HTML-страница 404, а не пустой список совпадений

### Requirement: Unknown and empty completion values mean all

HTML-страницы курса и задания SHALL трактовать неизвестный или пустой `completion` как «Все» без ошибки валидации. Система SHALL отражать этот режим в списке, переключателе и создаваемых ссылках навигации. Это правило SHALL NOT изменять JSON API или обработку отсутствующих ресурсов.

#### Scenario: Unknown completion on a course page
- **GIVEN** в курсе A есть задания с разными состояниями чек-листа, а в курсе B есть другие задания
- **WHEN** студент открывает курс A с `?completion=unexpected`
- **THEN** страница успешно открывается с выбранным режимом «Все» и показывает все задания A в прежнем порядке по ID, без заданий B
- **AND** ссылки на задания и переключатель используют нормализованный режим «Все», а неизвестное значение не переносится в ссылки

#### Scenario: Empty completion on a course page
- **WHEN** студент открывает существующий курс с `?completion=` либо `?completion`
- **THEN** страница показывает режим «Все» и тот же список, что и без фильтра, без ошибки валидации

#### Scenario: Unknown or empty completion in assignment navigation
- **WHEN** студент открывает существующее задание с неизвестным либо пустым `completion`
- **THEN** задание открывается без ошибки валидации
- **AND** ссылка `Back to course` и возврат после успешного удаления ведут в фактический курс задания с режимом «Все»

#### Scenario: Invalid completion does not conceal a missing resource
- **WHEN** студент открывает несуществующий курс либо задание с неизвестным или пустым `completion`
- **THEN** возвращается прежняя читаемая HTML-страница 404, а не ошибка валидации фильтра или пустой список

### Requirement: Three checklist-completion modes

Страница курса SHALL предлагать «Все», «Незавершённые» и «Завершённые». Задание SHALL считаться завершённым только при `total > 0` и `completed == total`; остальные задания SHALL считаться незавершёнными. Выбор фильтра SHALL только менять видимость, сохраняя данные и отображаемый прогресс.

#### Scenario: Complete classification of mixed checklists
- **GIVEN** в одном курсе есть A с `0 / 0`, B с `0 / 2`, C с `1 / 2` и D с `2 / 2`, а в другом курсе есть завершённое задание E
- **WHEN** студент последовательно выбирает каждый режим в первом курсе
- **THEN** «Все» показывает A, B, C, D; «Незавершённые» показывает A, B, C; «Завершённые» показывает только D
- **AND** E не показывается ни в одном режиме первого курса

#### Scenario: Filtering preserves coursework and progress
- **GIVEN** задания имеют описания, даты, ссылки на репозитории и сохранённые пункты чек-листа
- **WHEN** студент переключает режимы и возвращается к «Все»
- **THEN** задания и пункты не изменены и не удалены; их названия, описания, даты и ссылки сохранены
- **AND** прогресс по-прежнему показан счётчиками и целым процентом с округлением вниз; пустой чек-лист показывает `0 / 0`, `0%` и `No tasks`
- **AND** переключение не требует запроса сводки GitHub и не изменяет сохранённые ссылки

### Requirement: Filter membership follows saved checklist changes

При следующем показе страницы курса система SHALL определять принадлежность фильтру по текущим сохранённым пунктам чек-листа после завершения, повторного открытия, добавления и удаления. Отдельного ручного статуса задания SHALL NOT появляться.

#### Scenario: Completing the last incomplete task
- **GIVEN** задание имеет непустой незавершённый чек-лист
- **WHEN** студент сохраняет отметку последнего незавершённого пункта и возвращается к курсу
- **THEN** задание входит в «Завершённые» и не входит в «Незавершённые»

#### Scenario: Reopening or extending a completed checklist
- **GIVEN** чек-лист задания завершён
- **WHEN** студент снимает отметку с пункта либо добавляет новый незавершённый пункт и затем открывает курс
- **THEN** задание входит в «Незавершённые» и не входит в «Завершённые»

#### Scenario: Deleting the only incomplete task
- **GIVEN** в чек-листе есть один завершённый и один незавершённый пункт
- **WHEN** студент удаляет незавершённый пункт и затем открывает курс
- **THEN** оставшийся непустой чек-лист делает задание завершённым

#### Scenario: Deleting the last task
- **GIVEN** в завершённом задании остался один отмеченный пункт
- **WHEN** студент удаляет этот пункт и затем открывает курс
- **THEN** задание входит в «Незавершённые», не входит в «Завершённые» и показывает прежний пустой прогресс

### Requirement: URL-based filter continuity

Выбранный режим SHALL быть виден в интерфейсе и представлен в URL. Он SHALL сохраняться при обновлении страницы курса, переходе в задание и возврате в курс, включая изменения чек-листа на странице задания. Прямой вход без контекста фильтра SHALL сохранять прежнюю навигацию к курсу со всеми заданиями.

#### Scenario: Reloading or reopening a filtered URL
- **WHEN** студент выбирает «Незавершённые» либо «Завершённые», затем обновляет страницу или открывает её URL в новой вкладке
- **THEN** тот же режим выбран и список соответствует текущему сохранённому состоянию чек-листов

#### Scenario: Returning after a checklist change
- **GIVEN** студент открыл задание из отфильтрованного курса
- **WHEN** он изменяет чек-лист, дожидается успешного сохранения и перезагрузки страницы задания, затем выбирает `Back to course`
- **THEN** ссылка ведёт в исходный курс с тем же выбранным режимом, а задание показано или скрыто согласно новому состоянию

#### Scenario: Returning after assignment deletion
- **GIVEN** задание открыто из отфильтрованного списка курса
- **WHEN** студент подтверждает и успешно удаляет задание
- **THEN** браузер возвращается в его курс с тем же режимом, а задание отсутствует

#### Scenario: Direct assignment navigation keeps its existing default
- **WHEN** студент открывает задание по прямому URL без контекста фильтра и выбирает `Back to course`
- **THEN** он попадает в курс этого задания с режимом «Все»

### Requirement: Accessible controls and distinct empty states

Переключатель SHALL иметь понятные названия режимов и быть доступным с клавиатуры. Страница SHALL различать отсутствие заданий и отсутствие совпадений; при обоих состояниях SHALL оставаться доступны выбор «Все», редактирование курса и добавление задания с прежним поведением сохранения и ошибок.

#### Scenario: Keyboard selection
- **WHEN** студент выбирает режим с клавиатуры
- **THEN** фильтр применяется и текущий режим различим без необходимости использовать мышь

#### Scenario: Course has no assignments
- **GIVEN** курс не содержит заданий
- **WHEN** студент открывает страницу курса с любым допустимым режимом
- **THEN** показано прежнее сообщение `No assignments yet.` и доступны переключатель и существующие формы

#### Scenario: Filter has no matches
- **GIVEN** курс содержит задания, но ни одно не соответствует выбранному режиму
- **WHEN** показана страница курса
- **THEN** сообщение объясняет отсутствие совпадений по фильтру и отличается от `No assignments yet.`
- **AND** студент может выбрать «Все», увидеть существующие задания, редактировать курс и добавлять задания

#### Scenario: Creating an assignment while completed mode is selected
- **GIVEN** студент выбрал «Завершённые»
- **WHEN** он успешно добавляет задание через существующую форму
- **THEN** задание сохранено с прежними значениями по умолчанию и пустым чек-листом, текущий режим сохраняется
- **AND** новое задание доступно в «Все» и «Незавершённые», но не в «Завершённые»

### Requirement: Confirm successful creation of a filtered-out assignment

Если текущий фильтр скрывает успешно созданное задание, страница SHALL показать доступное подтверждение создания с названием задания и объяснением, что оно скрыто фильтром. Подтверждение SHALL содержать ссылку «Все» на список этого курса. Выбранный режим SHALL сохраняться до её нажатия. Подтверждение SHALL появляться только после успешного сохранения; новая отправка SHALL убирать прежнее подтверждение.

#### Scenario: Successful creation remains hidden under completed mode
- **GIVEN** выбран режим «Завершённые», независимо от наличия уже видимых завершённых заданий
- **WHEN** сервер подтверждает успешное создание задания через форму
- **THEN** страница показывает доступное сообщение, что указанное задание создано, но скрыто текущим фильтром; название отображается обычным текстом
- **AND** режим и URL с выбранным фильтром сохраняются, а неподходящее задание не добавляется в видимый список
- **AND** в подтверждении доступна ссылка «Все», а выбранный режим не сбрасывается автоматически

#### Scenario: Following the all link from the creation confirmation
- **GIVEN** показано подтверждение успешного создания задания, скрытого текущим фильтром
- **WHEN** студент активирует ссылку «Все» в подтверждении, в том числе с клавиатуры
- **THEN** открывается список всех заданий того же курса с выбранным режимом «Все», включая созданное задание
- **AND** задания других курсов не показываются

#### Scenario: First assignment changes an empty course into a filtered empty result
- **GIVEN** курс не содержит заданий и выбран режим «Завершённые»
- **WHEN** студент успешно создаёт первое задание
- **THEN** показано подтверждение создания и сообщение об отсутствии совпадений по фильтру
- **AND** сообщение `No assignments yet.` больше не показывается, а режим «Завершённые» сохранён

#### Scenario: Pending or failed creation never shows success
- **GIVEN** выбран режим «Завершённые»
- **WHEN** запрос создания ещё выполняется либо завершается ошибкой валидации, сервера или сети
- **THEN** подтверждение успеха не показывается
- **AND** при ошибке сохранены прежний режим, введённые значения и существующий способ отображения ошибки и повторной попытки

#### Scenario: A subsequent attempt clears an earlier success message
- **GIVEN** показано подтверждение предыдущего успешного создания скрытого задания
- **WHEN** студент отправляет форму ещё раз
- **THEN** предыдущее подтверждение убирается и не выдаётся за результат нового запроса
- **AND** только новый успешный ответ показывает подтверждение для нового задания

#### Scenario: Creation visible under all or incomplete keeps its existing flow
- **GIVEN** выбран режим «Все» либо «Незавершённые»
- **WHEN** студент успешно создаёт задание
- **THEN** оно видно в списке после прежнего обновления страницы, а выбранный режим сохраняется
