# Design

## Context

Мотивация, пять условий приёмки и границы описаны в [proposal.md](proposal.md); наблюдаемый контракт — в [spec delta](specs/course-assignment-filtering/spec.md).

`StudyFlow/studyflow/db.py` уже получает `total_tasks` и `completed_tasks` в запросе задания и возвращает задания курса по ID. `coursework.assignment_result` преобразует их в `progress`, а HTML и JSON используют `coursework.list_assignments`. Страница курса рендерится сервером, переключателя нет. JavaScript выполняет JSON-мутации и перезагружает текущую страницу.

В `assignment.html` ссылка `Back to course` и `data-course-url` пока содержат только ID курса. `assignments.js` использует `data-course-url` после удаления задания; `tasks.js` и сохранение задания используют `window.location.reload()`. Поэтому контекст фильтра достаточно передать в URL HTML-страницы задания и в оба адреса возврата.

Design нужен, чтобы до реализации определить границу HTML/API и передачу контекста между двумя страницами. Архитектура приложения, модель и зависимости не меняются.

## Goals / Non-Goals

**Goals:**

- Использовать существующие счётчики без дополнительных запросов пунктов для каждого задания и без сохранения производного состояния.
- Держать фильтр на границе HTML-представления, оставляя общий use case и JSON-маршруты с прежним поведением.
- Сохранить контекст через текущие перезагрузки и переход после удаления, не вводя состояние сессии.

**Non-Goals:**

- Общая система фильтров или новый слой сервисов/репозиториев.
- Изменение SQL, индексов или миграций ради текущего локального списка без пагинации.
- Управление произвольным `return_url`, настройка фильтра для пользователя или изменение языка всего интерфейса.

## Decisions

### 1. Фильтровать уже прочитанный список в HTML-пути

HTML-маршрут курса получает весь список через существующий `coursework.list_assignments` и отбирает записи по `progress.completed` и `progress.total`. Предикат завершённости: `total > 0 and completed == total`; незавершённость — его отрицание. Отбор сохраняет порядок исходного списка. Небольшой помощник, если нужен, остаётся в HTML-коде `web.py` без абстракции общего фильтра.

До отбора сохранить признак наличия заданий в полном списке, чтобы различать пустой курс и отсутствие совпадений. Не использовать процент или наличие репозитория как отдельный источник статуса.

Альтернативы: SQL-фильтрация уменьшила бы объём чтения на больших данных, но здесь добавляет сложность без требования по масштабу. Фильтрация только в JavaScript потребовала бы отдельной логики URL и состояния DOM. Серверная фильтрация соответствует текущему рендерингу; JavaScript меняется только для подтверждения создания скрытого задания, а не для отбора списка.

### 2. URL содержит только выбор представления

Техническая форма: `?completion=all|incomplete|completed` на HTML-страницах. Для режима по умолчанию ссылки могут опускать параметр, сохраняя существующие адреса `/courses/{id}` и `/assignments/{id}`. Допустимые значения — фиксированный набор, не произвольная строка для переноса в ссылки.

По решению review неизвестный либо пустой `completion` означает «Все». Оба HTML-маршрута принимают строку и нормализуют её перед отбором и построением ссылок; строгая enum-валидация с ответом 422 здесь не подходит. Отсутствующее значение также нормализуется в `all`. В генерируемые ссылки и данные формы попадает только нормализованный режим. Перенаправление ради исправления исходного URL не требуется. Отсутствие ресурса по-прежнему даёт 404 даже при неизвестном или пустом фильтре.

Переключатель реализуется обычными ссылками или GET-формой с доступными названиями и явным текущим режимом. Английский интерфейс сохраняется: `All`, `Incomplete`, `Completed` соответствуют согласованным трём режимам. Точная форма контрола не является новым продуктовым условием.

`completion` не объявляется параметром JSON API, не меняет тела мутаций и не хранится в SQLite, cookie или localStorage. Ссылки из общего списка курсов без параметра открывают «Все» независимо от предыдущей вкладки.

### 3. Передавать выбор через страницу задания

- Ссылки на задания в отфильтрованном курсе несут тот же допустимый `completion`.
- HTML-маршрут задания использует этот параметр только для построения адреса возврата. Он не ограничивает доступ к самому заданию по его текущей завершённости.
- Возврат строится из фактического `assignment.course_id`, а не из переданного клиентом ID курса или произвольного URL.
- `Back to course` и `data-course-url` получают один и тот же адрес с фильтром; существующий JavaScript удаления продолжает использовать этот адрес.
- Сохранение задания и изменения пунктов уже перезагружают текущий URL, поэтому контекст сохраняется без изменения JSON API и без новой обработки истории браузера.
- После смены завершённости студент остаётся на странице задания; при возврате тот же фильтр может скрыть это задание. Автоматического перенаправления при отметке пункта нет.

Альтернатива с Referer или глобальной настройкой ненадёжна для прямого входа и нескольких вкладок. Передача только режима в URL делает каждую ссылку самостоятельной.

### 4. Различать два пустых состояния

При пустом полном списке сохранить `No assignments yet.`. Если задания есть, но результат отбора пуст, показать отдельное сообщение, например `No assignments match this filter.`, и оставить доступ к «Все» и обеим существующим формам. Не скрывать и не перестраивать формы из-за выбранного режима.

Создание задания по-прежнему сохраняет его с пустым чек-листом. При «Завершённые» новое задание скрыто, а при «Все» и «Незавершённые» видно. По решению review скрытое успешное создание сопровождается отдельным подтверждением без сброса фильтра.

В `course.html` предусмотреть пустой контейнер статуса с `role="status"` рядом с формой и передать нормализованный режим через её data-атрибут. В `assignments.js` только после успешного POST создания под режимом `completed` показать, например, `Assignment “…” created. It is hidden by the current filter. Select All to see it.` Название брать из ответа API и выводить через `textContent`. Сохранить текущий URL и выбранный режим, очистить форму после успеха и вернуть доступность кнопок. Для этого случая не выполнять немедленный reload: он уничтожил бы статус. Успех не должен зависеть от появления задания в отфильтрованном списке.

`All` в подтверждении — настоящая ссылка «Все», доступная с клавиатуры, а не только текстовая подсказка о переключателе. Её адрес строится из текущего ID курса и нормализованного режима `all` (либо без параметра); она открывает все задания этого курса, включая созданное. Название задания остаётся отдельным текстовым узлом, ссылка — отдельным элементом. До явного перехода по ссылке сохранить текущий фильтр и URL; автоматически выбирать «Все» после создания нельзя.

Успешное создание первого задания делает курс непустым, даже если список «Завершённые» остаётся пуст. В этой ветке заменить `No assignments yet.` сообщением об отсутствии совпадений. Если завершённые задания уже видны, их список сохраняется. Для «Все»/«Незавершённые» и PATCH задания сохранить прежнюю перезагрузку текущего URL. Не добавлять новый endpoint, серверную сессию, параметры успеха в URL или хранилище браузера ради одноразового статуса.

В начале новой отправки убирать прежнее подтверждение. Пока запрос выполняется, при ошибке валидации, сервера или сети успех не показывать; сохранить существующее отображение ошибки, введённые значения и защиту от повторной отправки. Подтверждение остаётся до следующей отправки или ухода/обновления страницы, без таймера автоматического скрытия. Это статус результата конкретного запроса, не дополнительный сохранённый атрибут задания.

### 5. Проверять публичное поведение небольшими срезами

Расширять существующие HTTP/HTML-тесты и `tests/test_browser.py`, используя настоящую временную SQLite. Не тестировать частный помощник и не подменять внутренние domain/db-функции. Примеры прогресса и ожидаемых ID задавать буквально.

Для каждого среза при apply: один падающий тест наблюдаемого поведения, минимальная реализация, проверка; затем следующий срез. Не писать сначала весь набор тестов или все слои.

| Критерий | Основная проверка |
| --- | --- |
| AC1: режим по умолчанию и нормализация | HTTP/HTML: отсутствующий, неизвестный и пустой `completion`; список и нормализованные ссылки, изоляция курсов, прежний JSON-ответ и 404 |
| AC2: три режима | HTTP/HTML: A=`0/0`, B=`0/2`, C=`1/2`, D=`2/2`, чужой E; прогресс и данные неизменны |
| AC3: текущий чек-лист | HTTP/HTML: завершение, reopen, новый пункт, удаление незавершённого и последнего пункта |
| AC4: URL и возврат | Браузер: клавиатура, reload, открытие URL, переход в задание, изменение, возврат; также удаление и прямой вход |
| AC5: пустые состояния, формы и подтверждение | HTTP/HTML и браузер: пустой курс, отсутствие совпадений, сохранение курса; скрытое создание с доступным статусом и ссылкой «Все», неизменный фильтр до её нажатия; переход по ссылке с клавиатуры показывает созданное задание только в его курсе; переход пустого курса в отсутствие совпадений; отсутствие успеха при pending/ошибке/повторной попытке |

Существующие регрессионные тесты сохраняют проверки CRUD, ошибок, каскадов, прогресса и GitHub/MCP. Новые отдельные тесты всех старых CRUD-сценариев не дублировать.

## Risks / Trade-offs

- Потеря фильтра в одном из двух адресов возврата → проверить и ссылку, и успешное удаление задания в браузере.
- Пустой чек-лист ошибочно считается завершённым → использовать проверку `total > 0` и явный пример `0/0`.
- Новый режим случайно меняет API → фильтровать только HTML-путь и проверять неизменный JSON-список после выбора режима.
- Задание исчезает после возврата или не показывается после создания → сохранять видимый выбор и отдельное сообщение об отсутствии совпадений; скрытое успешное создание дополнительно подтверждать статусом.
- Сообщение об успехе потеряно из-за reload либо относится к предыдущему запросу → для скрытого создания показывать статус без reload и убирать его перед следующей отправкой; ошибки никогда не показывают успех.
- После создания первого задания остаётся ложное `No assignments yet.` → в ветке подтверждённого успеха обновить пустое состояние; проверить этот переход в браузере.
- Между открытой страницей и изменением в другой вкладке возможна устаревшая картинка → состояние обновляется при следующем запросе; live-обновление не требуется.
- Цена чтения всех заданий остаётся прежней → принять для текущего небольшого локального набора, не добавлять оптимизацию заранее.

## Migration Plan

Миграции данных и новые зависимости не нужны. При apply последовательно внести проверенные HTML-изменения, ограниченное изменение обработки создания в `assignments.js` и обновить `StudyFlow/spec.md` в той же реализации. Откат — вернуть HTML-код, шаблоны, JavaScript и связанные тесты/документацию; данные не требуют преобразования или сброса.

Baseline из explore: 218 основных тестов, 53 браузерных теста и `uv build` прошли при ручном запуске финального обработчика. После реализации из `StudyFlow/` выполнить `python3 scripts/verify_before_finish.py` и проверить результаты всех трёх команд, а не только exit самого обработчика. При ограничениях sandbox на запуск Chrome использовать разрешённый запуск вне неё, не менять проверки. Никаких live GitHub-вызовов для фильтра не требуется.
