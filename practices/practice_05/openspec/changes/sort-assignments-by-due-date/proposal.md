# Proposal

## Why

Сейчас задания курса показаны по ID, поэтому ближайший дедлайн может оказаться далеко в списке. Нужны постоянный порядок по дедлайну и отдельная вкладка «Просроченные», чтобы видеть оставшуюся работу с уже прошедшим сроком. Существующий фильтр завершённости и JSON API сохраняются.

## What Changes

- HTML-список курса сортируется по календарной дате по возрастанию; задания без даты идут в конце. При равных датах и внутри группы без даты — ID по возрастанию.
- К «Все», «Незавершённые» и «Завершённые» добавляется «Просроченные» (`completion=overdue`): незавершённые по чек-листу задания с `due_date < today`. Пустой чек-лист считается незавершённым; сегодняшние, будущие, завершённые и недатированные задания исключены.
- `today` — локальная календарная дата компьютера с веб-сервером StudyFlow, как согласовано с пользователем. Вычисляется один раз на запрос страницы курса, а не при запуске приложения. Часы и зона браузера не участвуют.
- В каждой вкладке сначала определяется видимость, затем применяется одна сортировка. Просроченные остаются во «Все» и «Незавершённые».
- Вкладка сохраняется в URL, при reload, переходе в задание и возврате после изменения/удаления. Скрытое успешное создание сохраняет вкладку и показывает подтверждение со ссылкой «Все», включая «Просроченные».

### Acceptance criteria

1. Во всех четырёх вкладках подходящие задания только текущего курса упорядочены по дедлайну, затем ID; без даты — в конце по ID. При отсутствии дат старые три вкладки сохраняют прежний порядок по ID.
2. «Просроченные» содержит ровно незавершённые задания с датой строго раньше сегодняшней локальной даты компьютера с StudyFlow. Проверены вчера/сегодня/завтра, пустой и частичный чек-лист, завершённость и отсутствие даты. Во «Все» и «Незавершённые» просроченные остаются.
3. День определяется заново на каждом GET курса: в локальную полночь сегодняшнее незавершённое задание становится просроченным при следующем чтении. Переходы месяца, года и високосного дня корректны; UTC и часы браузера не заменяют локальную дату. Открытая страница сама в полночь не обновляется.
4. URL сохраняет вкладку при возврате после изменения чек-листа, дедлайна, его очистки и удаления. Следующее чтение отражает сохранённые значения и актуальный день. Создание под «Просроченные» с прошлой датой показывает задание на месте по дедлайну; со скрывающей его датой или без даты показывает доступное подтверждение и ссылку «Все». Переход через полночь между показом формы и созданием не использует устаревший день формы.
5. Сохраняются прежние правила завершённости, прогресс, CRUD-валидация/ошибки, пустые состояния, доступность и GitHub/MCP. Отсутствующий, неизвестный или пустой `completion` означает «Все». JSON API сохраняет поля, ошибки, полный список и порядок по ID; данные заданий не переписываются ради отображения.

### Scope

Только HTML-страница курса и контекст возврата из задания. Сортировка постоянная, без переключателя и `sort` в URL. Четвёртая вкладка использует существующий `completion`, без второго независимого фильтра или их комбинаций. Это производное представление, без сохраняемого статуса «просрочено».

Не добавляются настройки часового пояса, UTC-дедлайны, время сдачи, уведомления, фоновые таймеры, пагинация, миграции, зависимости или изменения общего SQL/use case ради HTML. Системная локальная зона сервера используется без фиксации `Europe/Moscow`. Данные соседних курсов и JSON API не меняются.

### Previous behavior to preserve

- «Все» включает все задания курса; «Незавершённые» и «Завершённые» сохраняют классификацию: завершено только при `total > 0 && completed == total`.
- Нормализация недопустимого `completion`, фактический курс задания в возврате, 404 отсутствующих ресурсов, каскадное удаление и прежние формы остаются.
- Различаются пустой курс и отсутствие совпадений. Формы доступны в каждой вкладке; названия в подтверждениях выводятся обычным текстом, ошибки не выдают себя за успех.
- JSON возвращает задания по ID. HTML-порядок по ID заменяется правилом дедлайна; для одинаковых/отсутствующих дат ID остаётся критерием.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `course-assignment-filtering`: порядок HTML по дедлайну, четвёртая производная вкладка, источник локальной даты и её границы, навигация и создание в новом режиме. Два существующих обещания HTML-порядка по ID заменяются полными MODIFIED-блоками; остальные прежние требования продолжают действовать.

## Impact

- `StudyFlow/studyflow/web.py`: нормализация `overdue` в HTML-маршрутах, локальная дата на запрос, отбор и сортировка; общий `coursework.list_assignments`, SQL `ORDER BY id` и API остаются прежними.
- `StudyFlow/studyflow/templates/course.html` и `static/assignments.js`: доступная ссылка-вкладка и повторное чтение HTML после создания под Overdue, чтобы сервер определил актуальную видимость без часов браузера и изменения JSON.
- При apply — HTTP/HTML-тесты с реальной временной SQLite и управляемой внешней границей даты, браузерные проверки потока, обновление `StudyFlow/spec.md` и термина в `GLOSSARY.md` вместе с поведением. Отдельный ADR для обратимого правила отображения не требуется.
- В propose меняются только документы этого change. Код, тесты, main spec и архив предыдущего изменения не меняются; до apply, sync и archive остановиться.
