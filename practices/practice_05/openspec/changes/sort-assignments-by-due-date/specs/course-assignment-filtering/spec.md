# Spec Delta

## MODIFIED Requirements

### Requirement: Course-scoped assignment list with compatible defaults

Страница курса SHALL по умолчанию показывать все задания только этого курса по возрастанию дедлайна, без даты — в конце, при равной дате или отсутствии даты — по возрастанию ID. Фильтрация и сортировка SHALL затрагивать только HTML-представление списка и SHALL сохранять прежнее поведение JSON API и отсутствующих ресурсов.

#### Scenario: Opening a course without a filter

- **GIVEN** в курсе A есть задания с разными состояниями чек-листа и дедлайнами, а в курсе B есть другие задания
- **WHEN** студент открывает страницу курса A без фильтра
- **THEN** выбран режим «Все», показаны все задания A по возрастанию дедлайна, затем задания без даты; при равной дате и внутри группы без даты порядок определяется ID
- **AND** ни одного задания B не показано

#### Scenario: JSON list remains unfiltered

- **GIVEN** на странице курса выбран режим «Завершённые»
- **WHEN** клиент запрашивает `GET /api/courses/{course_id}/assignments`
- **THEN** возвращаются все задания этого курса в прежнем порядке и с прежним составом полей, включая прогресс и ссылку на репозиторий
- **AND** параметр фильтра не становится частью контракта JSON API
- **AND** порядок JSON-списка остаётся по ID по возрастанию, даже если даты требуют другого порядка на HTML-странице; параметр сортировки в API не добавляется

#### Scenario: Missing course remains a not-found page

- **WHEN** студент открывает страницу несуществующего курса с любым допустимым режимом
- **THEN** возвращается прежняя читаемая HTML-страница 404, а не пустой список совпадений

### Requirement: Unknown and empty completion values mean all

HTML-страницы курса и задания SHALL трактовать неизвестный или пустой `completion` как «Все» без ошибки валидации. Система SHALL отражать этот режим в списке, переключателе и создаваемых ссылках навигации. Это правило SHALL NOT изменять JSON API или обработку отсутствующих ресурсов.

#### Scenario: Unknown completion on a course page

- **GIVEN** в курсе A есть задания с разными состояниями чек-листа и дедлайнами, а в курсе B есть другие задания
- **WHEN** студент открывает курс A с `?completion=unexpected`
- **THEN** страница успешно открывается с выбранным режимом «Все» и показывает все задания A по возрастанию дедлайна, без даты — в конце, с ID как правилом разрешения равенства и без заданий B
- **AND** ссылки на задания и переключатель используют нормализованный режим «Все», а неизвестное значение не переносится в ссылки

#### Scenario: Empty completion on a course page

- **WHEN** студент открывает существующий курс с `?completion=` либо `?completion`
- **THEN** страница показывает режим «Все» и тот же список, что и без фильтра, без ошибки валидации

#### Scenario: Unknown or empty completion in assignment navigation

- **WHEN** студент открывает существующее задание с неизвестным либо пустым `completion`
- **THEN** задание открывается без ошибки валидации
- **AND** ссылка `Back to course` и возврат после успешного удаления ведут в фактический курс задания с режимом «Все»

#### Scenario: Invalid completion does not conceal a missing resource

- **WHEN** студент открывает несуществующий курс либо задание с неизвестным или пустым `completion`
- **THEN** возвращается прежняя читаемая HTML-страница 404, а не ошибка валидации фильтра или пустой список

## ADDED Requirements

### Requirement: Due-date ordering applies within every course tab

В каждой вкладке HTML-список курса SHALL показывать подходящие задания по возрастанию дедлайна, затем задания без даты. При равной дате и внутри группы без даты порядок SHALL определяться ID по возрастанию. Сортировка SHALL менять только порядок; текущий день SHALL влиять на отбор в «Просроченные», но не на ключ сортировки.

#### Scenario: Mixed dates and checklist states across four tabs

- **GIVEN** локальная дата сервера `2026-11-04`, в текущем курсе сохранены задания из таблицы, а другой курс содержит незавершённое задание с более ранней датой

| ID | Дедлайн | Чек-лист |
| --- | --- | --- |
| 1 | нет | пустой |
| 2 | 2026-11-20 | завершён |
| 3 | 2026-11-03 | частичный |
| 4 | 2026-11-03 | завершён |
| 5 | нет | завершён |
| 6 | 2026-11-01 | пустой |
| 7 | 2026-11-03 | незавершён |
| 8 | 2026-11-04 | незавершён |
| 9 | 2026-11-05 | незавершён |

- **WHEN** студент последовательно открывает четыре вкладки этого курса
- **THEN** «Все» показывает ID `[6, 3, 4, 7, 8, 9, 2, 1, 5]`
- **AND** «Незавершённые» показывает `[6, 3, 7, 8, 9, 1]`, «Завершённые» — `[4, 2, 5]`, «Просроченные» — `[6, 3, 7]`
- **AND** задание другого курса не показано; даты и прогресс сохранены

#### Scenario: All assignments have no due date

- **GIVEN** ни у одного задания курса нет даты
- **WHEN** студент открывает «Все», «Незавершённые» либо «Завершённые»
- **THEN** подходящие задания показаны по ID по возрастанию, как прежде
- **WHEN** студент открывает «Просроченные»
- **THEN** показано отсутствие совпадений, если в курсе есть задания

#### Scenario: Past dates remain in ordinary chronological order in all

- **GIVEN** незавершённые задания имеют даты `2000-01-01`, `2099-01-01` и отсутствие даты, а локальная дата сервера `2026-11-04`
- **WHEN** студент открывает «Все» либо «Незавершённые»
- **THEN** порядок дат равен `2000-01-01`, `2099-01-01`, отсутствие даты
- **AND** прошлая дата не удаляется и не выделяется в отдельную группу внутри этих вкладок

### Requirement: Overdue tab derives visibility from checklist and deadline

Страница курса SHALL предлагать вкладку «Просроченные» через `completion=overdue` наряду с тремя прежними режимами. В ней SHALL быть только задания текущего курса, для которых `not (total > 0 and completed == total)` и задана дата строго раньше `today`. Просроченность SHALL быть вычисляемым признаком, без нового сохраняемого статуса.

#### Scenario: Yesterday today tomorrow and missing deadline

- **GIVEN** локальная дата сервера `2026-11-04` и незавершённые задания с дедлайнами `2026-11-03`, `2026-11-04`, `2026-11-05` и без даты
- **WHEN** студент открывает «Просроченные»
- **THEN** показано только задание за `2026-11-03`; сегодняшнее, будущее и недатированное исключены

#### Scenario: Empty partial and completed checklists with past deadlines

- **GIVEN** все дедлайны раньше `today`, а чек-листы имеют `0 / 0`, `0 / 2`, `1 / 2` и `2 / 2`
- **WHEN** студент открывает «Просроченные»
- **THEN** первые три задания показаны, завершённое `2 / 2` исключено; прогресс не изменён

#### Scenario: Overdue assignments also remain in existing tabs

- **GIVEN** незавершённое задание с прошлой датой показано в «Просроченные»
- **WHEN** студент открывает «Все», затем «Незавершённые», затем «Завершённые»
- **THEN** задание есть в первых двух вкладках и отсутствует в третьей

#### Scenario: Checklist mutations recompute overdue visibility

- **GIVEN** дедлайн задания раньше `today`
- **WHEN** студент завершает последний незавершённый пункт и заново открывает курс
- **THEN** задание исчезает из «Просроченные» и входит в «Завершённые»
- **WHEN** он снимает отметку, добавляет незавершённый пункт либо удаляет все пункты и заново открывает курс
- **THEN** задание снова входит в «Просроченные», включая пустой чек-лист
- **AND** удаление единственного незавершённого пункта при наличии завершённых делает оставшийся непустой чек-лист завершённым и исключает задание

#### Scenario: Overdue is a known HTML mode without changing JSON

- **WHEN** студент открывает существующий курс с `?completion=overdue`
- **THEN** выбрана «Просроченные», а не нормализованная «Все»
- **WHEN** клиент читает JSON-список того же курса, в том числе после просмотра «Просроченные»
- **THEN** API возвращает все задания по ID с прежними полями; новый фильтр не становится контрактом API

### Requirement: Today is the server local calendar date on each course request

Для «Просроченные» система SHALL использовать локальную календарную дату компьютера с веб-сервером StudyFlow, вычисленную один раз для каждого GET курса. SHALL применяться строгое сравнение дат, без времени суток, UTC-преобразования дедлайна, зоны браузера или вычитания 24 часов. Следующий GET SHALL пересчитывать день; автоматического обновления открытой страницы в полночь SHALL NOT требоваться.

#### Scenario: Local midnight changes membership on the next request

- **GIVEN** незавершённое задание с датой `2026-11-04` и работающий без перезапуска сервер
- **WHEN** запрос курса обслуживается в локальное время `2026-11-04 23:59:59`
- **THEN** задание ещё не просрочено
- **WHEN** следующий GET обслуживается в `2026-11-05 00:00:00`
- **THEN** то же задание входит в «Просроченные» без изменения данных
- **AND** каждая отдельная страница использует один и тот же снимок `today` для всего списка

#### Scenario: Local date wins when UTC or browser date differs

- **GIVEN** на компьютере с StudyFlow локально `2026-11-05 00:30` в UTC+03, в UTC ещё `2026-11-04`, а браузер настроен на другую зону или дату
- **WHEN** открыт курс с незавершёнными заданиями за `2026-11-04` и `2026-11-05`
- **THEN** первое просрочено, второе нет; результат определяется локальной датой сервера, а не UTC или браузером
- **AND** UTC+03 — пример сценария, не фиксированная зона приложения

#### Scenario: Month year and leap-day boundaries

- **GIVEN** незавершённое задание с дедлайном D из таблицы

| D | Локальная дата запроса | Просрочено |
| --- | --- | --- |
| 2026-10-31 | 2026-11-01 | да |
| 2026-12-31 | 2027-01-01 | да |
| 2024-02-28 | 2024-02-29 | да |
| 2024-02-29 | 2024-02-29 | нет |
| 2024-02-29 | 2024-03-01 | да |

- **WHEN** сервер отображает «Просроченные»
- **THEN** принадлежность соответствует таблице без прибавления или вычитания фиксированного числа секунд

#### Scenario: An already open page has no midnight timer

- **GIVEN** страница курса открыта до локальной полуночи
- **WHEN** наступает следующий день без нового запроса страницы
- **THEN** автоматическое обновление не требуется
- **WHEN** студент обновляет страницу либо заново входит во вкладку
- **THEN** список соответствует дате нового запроса

### Requirement: Ordering and visibility reflect saved changes on the next course display

При следующем показе курса HTML-список SHALL использовать сохранённые дедлайны и чек-листы: сначала принадлежность выбранной вкладке, затем порядок по дедлайну и ID. Вкладка SHALL сохраняться, даже если изменение скрывает задание. Отдельного состояния сортировки SHALL NOT требоваться.

#### Scenario: Editing or clearing a date in the original three tabs

- **GIVEN** задание открыто из «Все», «Незавершённые» либо «Завершённые» и по чек-листу продолжает подходить этому режиму
- **WHEN** студент сохраняет более ранний дедлайн и возвращается в курс
- **THEN** вкладка сохранена и задание занимает место по новой дате и прежнему ID
- **WHEN** студент очищает дату и возвращается
- **THEN** задание перемещено в конец среди недатированных по ID

#### Scenario: Editing or clearing a date in overdue

- **GIVEN** незавершённое задание открыто из «Просроченные»
- **WHEN** студент меняет дедлайн на сегодня, будущую дату либо очищает его и возвращается
- **THEN** «Просроченные» сохранена, задание скрыто; при отсутствии других совпадений показано прежнее сообщение об отсутствии совпадений
- **WHEN** он затем сохраняет прошлую дату и снова открывает ту же вкладку курса
- **THEN** задание показано на месте по дедлайну и ID

#### Scenario: Visible creation under all or incomplete uses saved dates

- **GIVEN** выбрана «Все» либо «Незавершённые»
- **WHEN** студент успешно создаёт задание и страница обновляется прежним способом
- **THEN** новое задание появляется по сохранённому дедлайну либо в конце группы без даты; вкладка сохраняется

#### Scenario: All link after hidden creation uses the same ordering

- **GIVEN** под «Завершённые» либо «Просроченные» показано подтверждение создания скрытого задания
- **WHEN** студент активирует ссылку «Все»
- **THEN** все задания того же курса, включая созданное, показаны в порядке дедлайна и ID

### Requirement: Overdue tab preserves navigation creation feedback and empty states

`completion=overdue` SHALL сохраняться в URL и при переходах в задание и обратно, включая успешное удаление. Новая вкладка SHALL поддерживать прежние доступные элементы управления и пустые состояния. После создания SHALL применяться дата нового чтения курса: видимое задание показывается в списке, скрытое получает прежнее подтверждение со ссылкой «Все» без сброса вкладки.

#### Scenario: Reload detail back and deletion preserve overdue

- **GIVEN** студент выбрал «Просроченные»
- **WHEN** он обновляет страницу, открывает её URL отдельно, переходит в задание и возвращается после сохранённого изменения либо успешного удаления
- **THEN** `completion=overdue` сохранён, текущая вкладка различима, а результат заново вычислен и отсортирован
- **AND** возврат ведёт в фактический курс задания; отсутствующие ресурсы сохраняют HTML 404

#### Scenario: Keyboard navigation and overdue empty states

- **WHEN** студент выбирает «Просроченные» с клавиатуры
- **THEN** режим применяется и обозначен как текущий
- **AND** пустой курс показывает `No assignments yet.`, а непустой без просроченных — прежнее сообщение об отсутствии совпадений
- **AND** «Все», редактирование курса и добавление задания доступны в обоих состояниях

#### Scenario: Creating a visible overdue assignment

- **GIVEN** выбрана «Просроченные»
- **WHEN** сервер успешно создаёт задание с пустым чек-листом и датой раньше локального дня следующего чтения курса
- **THEN** новое задание видно в отсортированном списке, вкладка сохранена, сообщение о скрытом задании не показано

#### Scenario: Creating a hidden assignment under overdue

- **GIVEN** выбрана «Просроченные», в том числе в изначально пустом курсе
- **WHEN** сервер успешно создаёт задание без даты либо с датой сегодня или позже на момент следующего чтения курса
- **THEN** задание сохранено, скрыто из списка; доступное подтверждение выводит его название обычным текстом и ссылку «Все»
- **AND** вкладка и URL с фильтром сохранены; первое создание заменяет `No assignments yet.` на сообщение об отсутствии совпадений
- **AND** ожидание или ошибка POST не показывает успеха; новая отправка убирает прежнее подтверждение; ошибки сохраняют введённые значения и повторную попытку

#### Scenario: Creating across midnight uses fresh server date

- **GIVEN** форма «Просроченные» открыта при локальной дате `2026-11-04`
- **WHEN** создание задания за `2026-11-04` успешно завершается, а следующий запрос курса обслуживается уже `2026-11-05`
- **THEN** задание видно как просроченное; устаревшая дата формы и часы браузера не скрывают его и не вызывают ложное сообщение о скрытии

#### Scenario: A failed refresh after successful creation does not invite duplicate creation

- **GIVEN** POST во вкладке «Просроченные» подтвердил создание, но повторное чтение HTML не удалось
- **WHEN** страница сообщает результат операции
- **THEN** она подтверждает сохранение и объясняет невозможность обновить список, предлагает обновить текущую вкладку
- **AND** не сообщает об ошибке создания, не предлагает повторить POST и не утверждает без проверки, что задание скрыто фильтром
