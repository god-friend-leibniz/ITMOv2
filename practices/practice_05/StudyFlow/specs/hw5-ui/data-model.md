# Phase 1: данные и состояния UI

Основания: [spec.md](spec.md), неизменяемый [общий контракт 1.0](contracts/course-list.md), [UI-граница](contracts/ui-course-list.md). Здесь описаны существующие данные и состояние текущей страницы; новой доменной модели или таблиц нет.

## Существующие сущности

| Данные | Поля/отношения, используемые UI | Правила |
| --- | --- | --- |
| Course | `id`, `name`, `description`; владеет заданиями | Результат и ссылки относятся только к фактическому курсу. |
| Assignment | `id`, `course_id`, `title`, `description`, `due_date`, `repository`, `progress` | ID/родитель неизменяемы; дата необязательна; в DOM видимость передаёт `data-assignment-id`. |
| Task / Checklist | Задачи задания; `progress.completed`, `total`, `percent` в карточке | Пустой — 0 / 0, 0%, No tasks. UI не выводит новый статус по проценту. |
| Repository reference | Отсутствующая либо сохранённая пара owner/repo | Не влияет на вкладки, дату или порядок; текущие формы/обработка сохраняются. |

Валидация title/description/due_date/repository остаётся существующей серверной. Пользовательский и GitHub-текст экранируется. Просроченность и прогресс не сохраняются; SQLite, миграции, владение и каскады не меняются.

## Серверный снимок списка

`CourseListResult` — описательное имя результата, не новый класс/JSON DTO. Сервер рендерит существующие `course`, `assignments`, `completion`, `has_assignments` в стабильную HTML-секцию. `completion` — all/incomplete/completed/overdue; `has_assignments` — наличие любых заданий до фильтрации. DOM-порядок карточек — серверный порядок; UI его не пересчитывает.

Одна актуальная локальная дата используется сервером на результат; это не клиентское поле. В браузер не вводятся today, timezone или is_overdue. Отбор и показанный прогресс согласованы по счётчикам. Пустой результат с true и с false различимы, непустой с false недопустим.

## Краткоживущий контекст создания

| Состояние в assignments.js | Смысл и срок жизни |
| --- | --- |
| Курс и нормализованный режим | Из исходного контейнера; после принятого GET синхронизируются с новым контейнером и `assignmentForm.dataset.completion`. |
| `lastCreated`: отсутствует либо ID/title | Из последнего подтверждения создания; хранится в памяти страницы отдельно от формы, пока нужен для свежего чтения/повтора и сообщения. Не хранится в localStorage, cookie, URL или БД. |
| Состояние записи | Ожидание, pending, ошибка записи; управляет кнопкой, прежним write-error и сохранением ввода. |
| Состояние списка | current, refreshing, stale; управляет aria-busy, видимой актуальностью и повтором чтения. Независимо от исхода записи. |
| Сообщения | Ошибка записи отдельно от ошибки обновления; role=status для ожидания/успеха, role=alert для ошибки. Название — textContent. |

Это несколько переменных и обычные функции в существующем файле; библиотека конечных автоматов/общее хранилище не создаются. Во время POST или GET нельзя начать второй POST или GET этого потока. После ошибки чтения явное действие retry повторяет только GET. Новую намеренную отправку формы после завершения ожидания не трактовать как повтор уже сохранённого задания: предыдущая ошибка актуальности остаётся до успешного GET/ухода, а контекст lastCreated заменяется только новым подтверждённым созданием.

## Переходы

| Событие | Запись | Список и представление |
| --- | --- | --- |
| Первоначальный SSR | Ожидание | current; доверенный серверный список и режим. |
| Submit создания | pending, старое подтверждение скрыто | Список не подменяется несохранёнными полями; повтор GET/POST заблокирован. Существующая stale-ошибка не превращается в ошибку этой записи. |
| Подтверждённый отказ POST | Ошибка, ввод сохранён, повтор создания разрешён | Прежняя актуальность сохраняется; GET после неуспешной записи не запускается автоматически. |
| Сетевой исход POST неизвестен | Ошибка получения подтверждения, ввод сохранён | Нет утверждения успеха/гарантированного отсутствия записи, автоматического повтора POST нет. |
| POST подтверждён | Форма очищена, ID/title сохранены | refreshing: прежняя секция уже не представляется свежей, есть ожидание, начинается GET. |
| GET успешен и проверен | Успех записи не меняется | Одна замена секции → current; убраны stale/ошибка; ID есть — карточка, ID нет — hidden-confirmation со ссылкой All. |
| GET неуспешен | Успех записи сохраняется | stale; старый DOM не заменён, объявлены «Задание сохранено, но список обновить не удалось» и retry. Нет вывода о скрытости/новом empty. |
| Retry | Никакой записи | refreshing → current либо stale; тот же курс/режим, новый серверный снимок и дата, POST не выполняется. |
| Следующая намеренная запись отказала при stale | Ошибка новой записи, ввод сохранён | Прежние lastCreated и ошибка чтения остаются; можно обновить список без повторной записи. |
| Навигация/перезагрузка | Память текущей страницы завершается | Обычный SSR следующей страницы; фонового восстановления или автоповтора нет. |

PATCH деталей остаётся прежним сохранением с reload текущего адреса. DELETE сохраняет confirm и переход по серверному course_url. Эти операции не входят в новый поток создания/чтения.
