## Ручной локальный просмотр на отдельной БД

```sh
studyflow_ui_demo_dir=$(mktemp -d)
export STUDYFLOW_DB_PATH="$studyflow_ui_demo_dir/studyflow.sqlite3"
uv run python -m studyflow.db migrate

```

Используется новая временная БД, не пользовательская `data/studyflow.sqlite3`. Открыть страницу на loopback. Создать курс и задания с прошлым, сегодняшним, будущим и отсутствующим дедлайном; создать два одинаковых дедлайна с разными ID и названиями; добавить чек-листы с пустым, частичным и полным завершением. Проверить видимый порядок, четыре фильтра, оба empty-состояния и возврат через детали. Фильтры остаются обычными ссылками, адрес можно скопировать и открыть повторно. ## Матрица автоматической проверки

Все сценарии — публичная HTTP/HTML/browser-граница, временная SQLite и настоящий курс/задания/задачи. В tests/test_browser.py расширить нынешний course_server, не заменять domain/db или реальный шаблон. HTTP-правила сортировки/no-store/валидации принадлежат тестам логики.

| Сценарий | Действия и ожидаемое наблюдение |
| --- | --- |
| Четыре вкладки/порядок | Создать перемешанный набор из spec.md; во всех режимах сверить точную последовательность ссылок по ID с заранее заданным ожиданием. Равные даты — ID, без даты — в конце. |
| Выбор/доступность | Tab/Enter выбрать каждую ссылку; один aria-current=page, видимый фокус; reload и повторное открытие адреса сохраняют режим. При 360px все четыре ссылки достижимы, формы и поля подписаны. |
| Fallback и отсутствие ресурса | Нет/пустой/неизвестный completion → All; существующие 404 курса/деталей не превращаются в пустой список. |
| Детали/возврат | Overdue → assignment → PATCH или checklist complete/reopen/add/delete → Back to course. Режим и фактический курс сохранены; изменивший членство ID больше не появляется в этом фильтре. |
| DELETE и соседние сценарии | Отмена/подтверждение удаления сохраняют прежний confirm и return context. Repository edit/load/error и PATCH формы остаются регрессией. |
| Создание во всех режимах | Для каждого дедлайна и режима записать HTTP POST и последующий GET. После каждого подтверждённого POST есть свежий GET; карточка либо hidden-confirmation выбираются только по ID в успешном новом HTML. |
| Первое скрытое создание | Пустой курс → successful POST → GET pending: не выдавать новый empty до результата. На успешном GET has_assignments=true и no matches; поля очищены, фильтр сохранён, All показывает запись. |
| POST pending/ошибка | Удержать POST на HTTP-границе, повторить Enter/click: один POST. Подтверждённая ошибка сохраняет значения/режим и retry записи; неизвестный сетевой исход не объявляется гарантированным отсутствием и не повторяется автоматически. |
| GET pending | После POST удержать GET; форма уже очищена, сохранённые ID/title не потеряны, есть видимое ожидание и aria-busy, повтор submit/retry не даёт второго запроса. |
| Ошибка после записи | После реального успешного POST отказать именно следующему GET: network abort, 404 HTML, 503/500 JSON. Есть обязательное сообщение saved-but-not-refreshed, stale-пометка и type=button retry; нет ложного save-error, hidden или нового empty. |
| Повтор только чтения | Повторить отказ GET, затем разрешить настоящий GET; число POST остаётся 1, публичный JSON показывает одну запись. Состав/empty/сообщение обновляются лишь после успеха, stale и error снимаются. |
| Некорректный успех GET | Вернуть 200 с неверным media type; HTML без/с двумя контейнерами, чужим курсом/режимом, плохим boolean/ID или непустым false. DOM не заменён; это ошибка обновления с тем же GET retry. Не проверять серверный алгоритм в JS. |
| Полночь | Fixture получает изменяемый источник через предложенный local_date_provider: форма при D, POST/GET при D+1; также POST при D и GET при D+1. Дедлайн D включён в overdue; браузерные часы намеренно могут оставаться D. ОС пользователя не менять. |
| Безопасный текст | Title с `<b>`/`<script>` виден текстом в карточке и confirmation; код/inline handlers не выполняются. Новые тексты не вставляются через innerHTML; скрипты полного GET не переподключаются. |
| Фокус и сообщения | Pending/hidden-success/ошибка доступны status/alert. Retry с клавиатуры на ошибке сохраняет фокус; на успехе скрывающаяся кнопка передаёт его Add assignment. Обычный refresh не забирает фокус из формы. |
| Независимость исходов | После saved + failed GET намеренная новая запись отказала: сохранён первый ID и сообщение stale, можно повторить только чтение. Ошибка новой записи сохраняет её ввод, не создаёт дубль первой. |

Сетевые отказы в браузере применяются к конкретному GET и освобождаются перед retry; успешные ответы по возможности пропускают настоящий сервер. Ошибочные HTML-ответы — проверка потребления транспорта, не замена бизнес-отбора. Полночь проверяет публичный серверный источник времени, а не JS Date и не внутренние функции.
