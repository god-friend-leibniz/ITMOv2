## Внешняя зависимость: сервер логики

**G-server** — предоставленная командой логики реализация технического интерфейса 0.1 должна быть доступна в собственном интеграционном checkout до приёмки соответствующих browser-сценариев:

- существующий HTML GET курса отдаёт окончательный состав/порядок, нормализованный `completion`, `has_assignments` до фильтрации и `Cache-Control: no-store`;
- оба HTML-маршрута поддерживают overdue/fallback и возврат в фактический курс; ошибки чтения остаются 404 / 503 DATABASE_BUSY / 500 INTERNAL_ERROR;
- публичный `create_app(local_date_provider=...)` позволяет управлять серверной датой через browser fixture без изменения часов ОС. Каждый результат использует одну текущую локальную дату;
- прежние POST/JSON API не меняются. Реальный `course.html` с маркерами поставляет UI, а не серверный тестовый дубль.

G-server — зависимость от другой стороны, **не задача написать сервер силами UI**. Способ доставки серверных изменений сюда не задаётся. Если их ещё нет, фиксировать блокировку интеграции; не обходить её выдуманным протоколом, monkeypatch внутренних слоёв, фальшивым HTML успеха или постоянно пропускаемым тестом. Ошибочный ответ допустимо исказить на HTTP-границе именно для проверки отказа потребления; успешные списки проходят через настоящий сервер/шаблон.

**G-integrated** — после UI-маркеров настоящего шаблона совместно проходят browser-сценарии и предоставленные логикой HTTP/HTML-проверки. T003 не требует прохождения ещё невозможных тестов маркеров до T005; окончательная проверка этого стыка — T038. Отсутствие сервера не считается ожидаемым TDD red UI и не позволяет завершить историю.
