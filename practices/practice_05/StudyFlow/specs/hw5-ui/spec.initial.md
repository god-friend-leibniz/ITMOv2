# Feature Specification: Список по дедлайнам и вкладка «Просроченные» — UI

**Feature Branch**: `codex/hw5-ui`

**Created**: 2026-10-25

**Status**: Draft — независимое предложение UI до межкомандного согласования

**Input**: User description: «Задания курса сортируются по дедлайну по возрастанию, без даты — в конце, равные даты — по ID. Новая вкладка “Просроченные”: незавершённые по чек-листу задания с датой раньше сегодняшней локальной даты компьютера с StudyFlow. Сегодняшние, завершённые и без даты исключены. Просроченные остаются во “Все” и “Незавершённые”. JSON API сохраняет поведение. Ответственность UI: список, вкладки, навигация, пустые состояния, ошибки, создание, доступность и ожидания от логики. Только спецификация».

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Видеть задания в порядке дедлайнов (Priority: P1)

Студент открывает курс и видит задания с более ранними календарными датами первыми, чтобы выбирать работу без ручного поиска.

**Why this priority**: Порядок меняется для всех пользователей страницы курса.

**Independent Test**: Открыть курс с перемешанными и одинаковыми датами и отсутствующими датами; сверить последовательность ссылок во всех вкладках.

**Acceptance Scenarios**:

1. **Given** задания курса с ID 11 (без даты), 12 (2026-10-27), 13 (2026-10-24), 14 (2026-10-24), 15 (без даты), **When** студент открывает «Все», **Then** видит ровно 13, 14, 12, 11, 15 независимо от названий.
2. **Given** в «Незавершённых» и «Завершённых» есть задания с разными и равными датами и без даты, **When** студент выбирает вкладку, **Then** её состав сохраняет прежние правила завершённости, а порядок следует тому же правилу дат и ID.
3. **Given** студент изменил или очистил дедлайн в деталях, **When** возвращается в курс, **Then** задание занимает соответствующее новой дате место, если входит в текущую вкладку.

---

### User Story 2 - Открыть просроченную работу (Priority: P1)

Студент выбирает «Просроченные», чтобы выделить незавершённую работу с уже прошедшим дедлайном.

**Why this priority**: Это основной новый способ отбора заданий.

**Independent Test**: При локальной дате 2026-10-25 открыть вкладку для набора ниже; проверить состав, порядок и отсутствие заданий другого курса.

**Acceptance Scenarios**:

1. **Given** задания из таблицы и локальная дата 2026-10-25, **When** студент выбирает «Просроченные», **Then** видит только 23, 21 в этом порядке.

   | ID | Дедлайн | Выполнено / всего задач | В «Просроченных» |
   | --- | --- | --- | --- |
   | 21 | 2026-10-24 | 0 / 0 | Да |
   | 22 | 2026-10-24 | 1 / 1 | Нет |
   | 23 | 2026-10-23 | 1 / 2 | Да |
   | 24 | 2026-10-25 | 0 / 1 | Нет |
   | 25 | 2026-10-26 | 0 / 1 | Нет |
   | 26 | Нет | 0 / 1 | Нет |

2. **Given** 21 и 23 просрочены, **When** студент открывает «Все» или «Незавершённые», **Then** оба остаются там, каждое ровно один раз, в общем порядке дедлайнов.
3. **Given** студент завершил последнюю незавершённую задачу просроченного задания, **When** возвращается в курс, **Then** оно исчезает из «Просроченных» и «Незавершённых», оставаясь во «Все» и «Завершённых»; после повторного открытия задачи снова подходит «Просроченным».

---

### User Story 3 - Сохранять выбранную вкладку (Priority: P2)

Студент переходит к заданию, меняет его или чек-лист и возвращается к тому же срезу курса.

**Why this priority**: Существующая навигация уже сохраняет фильтр; новая вкладка должна вести себя последовательно.

**Independent Test**: Выбрать «Просроченные» с клавиатуры, перезагрузить страницу, открыть её адрес отдельно и пройти курс → детали → изменение → возврат, затем удаление с подтверждением.

**Acceptance Scenarios**:

1. **Given** выбран любой из четырёх режимов, **When** студент перезагружает страницу или открывает её адрес в другой вкладке браузера, **Then** сохраняются режим и видимый текущий выбор; состав соответствует актуальным сохранённым данным и текущей локальной дате.
2. **Given** задание открыто из «Просроченных», **When** студент сохраняет изменения задания или задач, **Then** детали остаются доступны с контекстом возврата; «Back to course» возвращает в «Просроченные» фактического курса, даже если задание больше не подходит фильтру.
3. **Given** задание открыто из выбранной вкладки, **When** студент подтверждает удаление, **Then** возвращается в ту же вкладку его курса; отмена оставляет детали и данные на месте.
4. **Given** в адресе курса или деталей нет режима либо режим пустой/неизвестный, **When** студент открывает адрес, **Then** используется «Все» без ошибки валидации фильтра; отсутствующие курс и задание сохраняют понятную страницу «не найдено».

---

### User Story 4 - Создавать задания и понимать пустой список (Priority: P2)

Студент создаёт задания из любой вкладки и отличает успешное создание скрытого задания от ошибки или отсутствия заданий в курсе.

**Why this priority**: Новое задание имеет пустой чек-лист, но видимость в «Просроченных» зависит ещё и от даты; молчаливое отсутствие созданного задания вводило бы в заблуждение.

**Independent Test**: Создать задания с прошлой, сегодняшней, будущей и пустой датой из «Просроченных»; повторить скрытое создание из «Завершённых», проверить ошибки, повторную отправку и оба пустых состояния.

**Acceptance Scenarios**:

1. **Given** открыты «Просроченные» и дата компьютера 2026-10-25, **When** успешно создано задание с дедлайном 2026-10-24, **Then** оно видно на правильном месте после обновления страницы, вкладка сохранена. Во «Все» и «Незавершённых» создание также сохраняет прежнее обновление страницы и показывает задание в порядке дедлайнов.
2. **Given** открыты «Просроченные», **When** успешно создано задание на сегодня, будущее или без даты, **Then** режим и список не переключаются, показано подтверждение с сохранённым названием, объяснением «скрыто текущим фильтром» и ссылкой «Все» этого курса, поля очищены. В «Завершённых» это поведение сохраняется для любого нового задания.
3. **Given** в курсе нет заданий, **When** открывается любая вкладка, **Then** виден `No assignments yet.`; если задания есть, но совпадений нет — `No assignments match this filter.`. Навигация, создание и редактирование курса доступны в обоих случаях. Создание первого скрытого задания меняет сообщение на отсутствие совпадений.
4. **Given** отправляется форма, **When** запрос ожидает результата, **Then** повторная отправка заблокирована, прежнее подтверждение скрыто; **When** возникает ошибка валидации, сервера или сети, **Then** видна понятная ошибка, ввод и режим сохранены, повтор доступен, подтверждения успеха нет.
5. **Given** показано подтверждение скрытого создания, **When** студент активирует его ссылку «Все», **Then** видит созданное задание в том же курсе. Название с разметкой показывается обычным текстом. Подтверждение исчезает при следующей отправке, переходе или перезагрузке, без таймера и сохранения между страницами.

### Edge Cases

- Пустой чек-лист остаётся незавершённым: `0 / 0`, `0%`, `No tasks`; прошедшая дата включает его в «Просроченные». Это не новый статус задания.
- Удаление последней задачи возвращает незавершённость; удаление единственной незавершённой задачи при оставшихся завершённых может убрать задание из «Просроченных». Результат виден при следующем открытии списка.
- Равные даты у просроченных заданий разрешаются возрастанием ID; задания без даты тоже идут по ID в конце каждой подходящей вкладки.
- Следующая загрузка курса, переключение вкладки или перезагрузка после полуночи использует новую локальную дату компьютера с StudyFlow. Автоматическое обновление открытой страницы не требуется.
- Сегодняшнее задание исключено весь локальный день независимо от времени суток; UTC-дата и часовой пояс отдельно открытого браузера не заменяют дату компьютера с приложением.
- Изменение даты на будущую или очистка даты убирает задание из «Просроченных» при возврате, сохраняя вкладку; это не ошибка и не удаление.
- При ошибке чтения сохраняется существующая обратная связь об ошибке; ошибка не представляется успешной пустой выборкой. Недоступность GitHub не блокирует список, фильтры и CRUD.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Страница курса MUST показывать только его задания по дедлайну от раннего к позднему, затем без даты; равные даты и отсутствие дат разрешаются возрастанием ID. Правило действует в каждой вкладке (US1; US2.1).
- **FR-002**: UI MUST сохранять «Все», «Незавершённые», «Завершённые» и добавлять «Просроченные»: только незавершённые по чек-листу задания с датой строго раньше сегодняшней локальной даты компьютера с StudyFlow. Сегодняшние, будущие, завершённые и без даты исключены. Просроченные остаются во «Все» и «Незавершённых» (US2).
- **FR-003**: Все четыре вкладки MUST иметь понятные названия, видимый и доступный вспомогательным технологиям текущий выбор, управление Tab/Enter и видимый фокус. Порядок чтения и обхода ссылок заданий MUST совпадать с порядком списка; все режимы доступны и при узком окне (US3.1; SC-005).
- **FR-004**: UI MUST сохранять режим в адресе, при перезагрузке, прямом открытии, переходе в детали, обновлении деталей и возврате/удалении. Контекст режима MUST NOT ограничивать доступ к деталям. Пустой/неизвестный режим означает «Все» (US3).
- **FR-005**: Карточки MUST сохранять название-ссылку, описание и дедлайн при наличии, счётчики и процент; пустой чек-лист — `No tasks`. Сортировка и вкладки MUST NOT менять данные или вводить ручное завершение задания (US1–US2).
- **FR-006**: UI MUST различать пустой курс и отсутствие совпадений, сохраняя навигацию и формы; существующие ошибки чтения и страницы «не найдено» MUST NOT подменяться пустым списком (US3.4; US4.3; Edge Cases).
- **FR-007**: Создание MUST сохранять вкладку. Подходящее ей задание появляется в порядке дедлайнов через прежнее обновление страницы; скрытое получает подтверждение с сохранённым названием, причиной отсутствия и ссылкой «Все», без немедленной перезагрузки и вставки скрытой карточки. Поля очищаются только после успеха (US4.1–US4.3, US4.5).
- **FR-008**: Формы MUST сохранять подписи, блокировку повторного запроса во время ожидания, ввод при ошибках и возможность повтора. Ошибка и подтверждение MUST объявляться вспомогательным технологиям; устаревший успех скрывается перед отправкой; пользовательский текст остаётся обычным текстом (US4.4–US4.5).
- **FR-009**: Список MUST отражать сохранённые изменения чек-листа, даты и наступление следующего локального дня при следующей загрузке; фонового обновления не требуется (US1.3; US2.3; Edge Cases).
- **FR-010**: Существующие сценарии редактирования курса/задания, чек-листа, подтверждения каскадного удаления и явной загрузки репозитория MUST сохраняться. JSON API MUST сохранять поля, коды/ошибки, нефильтрованный состав списка и порядок по ID, включая обращения с параметрами HTML-фильтра (US3–US4; сохранность действующего контракта).

### Key Entities *(include if feature involves data)*

- **Course / курс**: существующая область списка; задания других курсов исключены.
- **Assignment / задание**: существующее задание с неизменяемым ID, названием, описанием, необязательным дедлайном и прогрессом; новых сохраняемых полей не требуется.
- **Assignment progress / прогресс задания**: существующие выполнено/всего и процент. Завершён только непустой чек-лист со всеми завершёнными задачами; остальные задания незавершены.
- **Просроченное задание**: временная принадлежность к выборке по дедлайну и незавершённости, не сохраняемый статус, оценка или факт сдачи.
- **Текущая вкладка**: выбор представления и контекст возврата, не характеристика задания.

### Ожидания UI от команды логики — предложения для согласования

Правила состава и порядка заданы общей целью. Ниже перечислен необходимый UI результат; это ещё не согласованный межкомандный контракт. Алгоритм, слои и место вычислений другой команды здесь не определяются.

| Предложение | Ожидаемые данные и результат для UI |
| --- | --- |
| **P-01: список** | Упорядоченный список выбранного курса/режима; для карточек — существующие ID, название, описание, дата или её отсутствие, выполнено/всего и процент. Новая сохраняемая отметка завершённости или просрочки не нужна. |
| **P-02: контекст** | Нормализованный режим и сведения, есть ли вообще задания курса до фильтрации: для текущего выбора и двух пустых состояний. Предлагается расширить существующий HTML-контекст `completion` значением `overdue`, сохранив остальные значения и fallback во «Все». |
| **P-03: локальная дата** | Единая дата компьютера с StudyFlow для состава страницы и видимости созданного задания. UI нужен достаточный контекст для этого решения без изменения JSON API и без использования UTC-даты или зоны браузера. Форма передачи не выбрана. |
| **P-04: сохранение и ошибки** | Прежний результат успешного создания с сохранёнными названием, датой и пустым прогрессом; прежние ошибки валидации/сервера. Чтения и изменения coursework не зависят от GitHub. |

**Вопросы к команде логики**:

1. Подтверждаем ли `completion=overdue` для новой HTML-вкладки и контекста возврата при сохранении трёх прежних значений и fallback во «Все» (P-02)?
2. Каким результатом на границе с UI обеспечим упорядоченный список, режим и наличие любых заданий курса, сохранив прежний JSON-список (P-01–P-02)? Внутренний способ сортировки/фильтрации остаётся за командой логики.
3. Как передадим достаточный UI контекст локальной даты для обратной связи при создании, в том числе если форма открыта до полуночи, а сохранена после, без расширения JSON API (P-03–P-04)? Предлагаем оценивать видимость по локальной дате успешного создания, а не по устаревшей дате открытия формы.

Это вопросы интеграционного согласования, а не неясности общей продуктовой цели; выбор реализации здесь не делается.

## Success Criteria *(mandatory)*

### Measurable Outcomes

Пять основных условий приёмки UI:

- **SC-001 — Порядок**: Во всех четырёх вкладках 100% показанных заданий следуют правилу «дата по возрастанию → без даты → ID при равенстве»; US1.1 даёт ровно 13, 14, 12, 11, 15 во «Все».
- **SC-002 — Состав**: На наборе US2.1 при локальной дате 2026-10-25 «Просроченные» показывают ровно 23, 21; оба остаются во «Все» и «Незавершённых», без чужих заданий, дублей и изменения прогресса.
- **SC-003 — Контекст**: Все четыре режима сохраняют выбор при повторном открытии адреса, перезагрузке, переходе в детали, сохранении, возврате и подтверждённом удалении; изменение принадлежности задания не переключает студента автоматически во «Все».
- **SC-004 — Обратная связь**: Каждый из четырёх вариантов даты при создании из «Просроченных» даёт ровно одно ожидаемое представление: видимое задание либо подтверждение скрытого создания со ссылкой во «Все». Две пустые ситуации различимы; все три вида ошибки US4.4 сохраняют ввод, режим и возможность повтора.
- **SC-005 — Доступность и прежние сценарии**: Весь путь «выбрать вкладку → открыть задание → вернуться» и ссылка из подтверждения доступны с клавиатуры с видимым фокусом; текущий выбор, ошибка и подтверждение определимы вспомогательными технологиями. Во всех сценариях US1–US4 сохраняются карточки, редактирование, чек-лист и подтверждение удаления.

## Assumptions

- Основания: корневые `AGENTS.md`, `spec.md`, `GLOSSARY.md`, конституция Spec Kit, текущие страницы курса/задания, их обработчики взаимодействий и относящиеся HTTP/HTML- и browser-тесты. Запрещённые каталоги, другие worktree/чаты и Git-история не использовались.
- UI сейчас англоязычный. Русские названия обозначают `All`, `Incomplete`, `Completed` и новую `Overdue`; предполагается сохранить язык UI и прежние тексты ошибок/пустых состояний. Локализация приложения в объём фичи не входит.
- «Вкладки» — существующие навигационные ссылки фильтра с адресом и текущим выбором. Перестройка навигации, отдельный выбор порядка, счётчики вкладок, значки срочности и таймеры не требуются.

- Пустой чек-лист остаётся незавершённым. Репозиторий не влияет на вкладки/прогресс. Текущий режим не ограничивает доступ к деталям.
