## Наблюдаемое поведение

- Реальный HTML содержит согласованные маркеры технического интерфейса 0.1; Overdue — обычная ссылка с серверным completion, aria-current и прежним контекстом возврата.
- UI отображает серверный состав и DOM-порядок. После каждого подтверждённого создания выполняется свежий HTML GET с no-store. До его успеха не объявляются новое пустое состояние или скрытость задания.
- Проверяются HTTP `200`/`text/html`, единственность секции, курс/режим, boolean, положительные уникальные ID каждой карточки, empty-согласованность и отсутствие form/script внутри секции. Только после проверки заменяется секция; формы и live-области остаются в документе. Даты, прогресс и правильность серверной сортировки UI не вычисляет.
- Успех записи и ошибка чтения разделены; форма очищается по подтверждению записи. Ошибка обновления сохраняет старый список как неактуальный и позволяет повторить только GET. Новая намеренная запись не стирает старый подтверждённый контекст при отказе.
- Native links, labels, role=status/alert, aria-busy, видимая stale-пометка, клавиатурный retry и управление фокусом проверены в браузере. Текст экранируется; скрипты полного документа не подключаются повторно. PATCH/reload, checklist, DELETE/confirm/return и repository-сценарии сохранены.

## Последовательные проверки поведения

Все browser-проверки используют настоящий FastAPI/uvicorn, временную SQLite и публичные HTTP-действия. Источник даты передаётся только через публичный create_app(local_date_provider=...). Сбои и повреждения конкретного GET вводятся на браузерной HTTP-границе; успешные ответы получаются от настоящего сервера и настоящего шаблона. Для повреждённых ответов берётся реальный HTML через route.fetch(), затем изменяется только проверяемая часть; альтернативный шаблон/endpoint не создаётся.
