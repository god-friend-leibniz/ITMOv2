# UI-потребление технического интерфейса списка курса

Дата: 2026-10-25. **Статус: UI признаёт предложенный логикой технический интерфейс 0.1 совместимым и планирует его использование.** Это не новая редакция общего контракта и не доказательство реализации.

Основания: неизменяемый [общий контракт 1.0](course-list.md), [UI spec](../spec.md), разрешённый `specs/hw5-logic/contracts/technical-interface.md` в worktree логики. Ниже сохранены его URL и обязательные маркеры. Внешний документ не изменяется; UI-внутренние селекторы не создают требований к маршрутам/алгоритмам сервера.

## Последовательность на границе

| Операция | Потребление UI |
| --- | --- |
| Создать | Прежний `POST /api/courses/{course_id}/assignments`, существующие JSON body/201/error; ID/title подтверждённого задания сохраняются в памяти, форма очищается. |
| Читать после записи / retry | Существующий `GET /courses/{course_id}?completion={mode}`; для all можно без query. `Accept: text/html`, fetch `cache: "no-store"`. После каждого подтверждённого создания во всех режимах, после ошибки — только этот GET. |
| Серверный успех | `200 text/html` (charset допустим), `Cache-Control: no-store`, полный HTML с одним контейнером результата. Существующие context keys: course, assignments, completion, has_assignments. |
| Серверная ошибка | HTML 404 либо существующие JSON 503 DATABASE_BUSY/500 INTERNAL_ERROR; UI не требует единого формата тела ошибок и не вставляет их в список. |

После получения text/html UI разбирает документ через DOMParser, проверяет нужную секцию и импортирует только её. До успешной проверки текущий DOM сохраняется. Нет document.write, вставки body/форм, выполнения/подключения скриптов из ответа или новой API-схемы.

## Принятые серверные маркеры

| Маркер из предложения 0.1 | Проверка/использование UI |
| --- | --- |
| `#course-assignment-list` | Ровно один в документе; включает Assignments heading, nav, карточки и empty. Исключает формы, сообщения сохранения/обновления и retry. |
| `data-course-id` | Положительный ID, точно соответствует текущему курсу; не брать курс из произвольного URL ошибки. |
| `data-completion` | Только all/incomplete/completed/overdue, совпадает с запрошенным уже нормализованным режимом. |
| `data-has-assignments` | Только строки true/false, по полному набору курса до отбора. Непустой результат с false отклоняется. |
| `[data-assignment-id]` | На каждой видимой карточке один положительный уникальный ID; DOM-порядок окончательный. Искать внутри нового контейнера, не всей старой страницы. |
| `#assignments-empty` | При отсутствии карточек ровно один; при непустом результате отсутствует. Сервер задаёт прежний текст по has_assignments, UI не придумывает новый empty при сбое. |
| `#assignment-form[data-completion]` | На оставшейся форме синхронизировать с проверенным контейнером; JSON URL не меняется. |

Ссылки карточек и фильтров сохраняют серверный режим; All допускает канонический URL без query. Положительность/уникальность маркеров — проверка целостности, не алгоритм отбора. Проверять даты, прогресс или правильность сортировки клиентским алгоритмом не нужно.

Ошибка сети/чтения тела, не-200, media type не text/html, отсутствие/дублирование контейнера, неверный курс/режим/boolean/ID или противоречие списка и empty — отказ обновления. DOM ещё не меняется. Проверки остаются конкретными условиями текущего протокола, без общего валидатора или попыток исправить результат.

В секции не должно быть form/script; их наличие отклоняется. Все данные карточек рендерятся с существующим Jinja escaping. DOMParser не является санитайзером; новые safe-фильтры, inline handlers и HTML из POST title не добавляются. Название для подтверждения устанавливается через textContent.

## Внутренние UI-элементы вне заменяемой секции

| Элемент | Назначение |
| --- | --- |
| Существующий `#assignment-error[role=alert]` | Ошибка самой записи, сохранение ввода; не использовать для ошибки GET после подтверждения записи. |
| Существующий `#assignment-success[role=status]` | Подтверждение создания с textContent сохранённого title; при скрытом ID — пояснение и All фактического курса. Ссылка скрыта, если она не нужна. |
| `#assignment-refresh-status[role=status]` | Сообщение о выполняющемся обновлении; live-область остаётся в DOM. |
| `#assignment-refresh-error[role=alert]` | «Задание сохранено, но список обновить не удалось». Не меняет известный исход POST. |
| `#assignment-list-stale-note` | Видимая текстовая пометка неактуальности прежней секции, связанная с ней через aria-describedby при stale. Одного цвета недостаточно. |
| `#assignment-refresh-retry[type=button]` | «Обновить список»; один обработчик вне заменяемой секции; повторяет только GET. |

Эти имена выбираются UI; серверная логика не обращается к ним. На секции применяются aria-busy и локальная CSS-пометка stale. Серверный HTML не обязан выводить клиентское состояние предыдущего POST: оно остаётся в текущем документе.

## Применение и фокус

1. До POST скрыть прежнее подтверждение; блокировать повторную отправку. Если список уже stale от предыдущего сохранения, ошибка его актуальности сохраняется отдельно от новой записи.
2. После подтверждённого POST хранить ID/title отдельно, очистить форму, пометить прежний список неактуальным и обозначить GET pending. Во время POST/GET отключены повторные submit/retry; заполнение формы само по себе не запускает запись.
3. На успешном GET проверить весь результат в отдельном документе, импортировать секцию и заменить старую одной операцией. Обновить ссылку на контейнер и dataset режима формы. Не подключать JS заново: навигационные ссылки не требуют обработчиков, формы/сообщения/кнопка retry остались в DOM.
4. Снять busy/stale/error и сравнить созданный ID с ID карточек нового контейнера. Есть — показать готовый список и подтвердить создание; нет — hidden-confirmation и All. Даты браузера/формы не участвуют.
5. На отказе сохранить старую секцию и известный успех, снять busy, оставить stale и retry. Не объявлять ни пустой успех, ни скрытость. Повторный GET использует тот же курс/режим; новый серверный результат может иметь новую дату.
6. Если при успешном retry фокус был на скрываемой кнопке, перевести его на стабильную кнопку Add assignment после её разблокировки. В остальных случаях не перемещать фокус из формы. На повторной ошибке фокус и доступный retry сохраняются.

Обычные ссылки фильтра работают Tab/Enter, текущая — aria-current=page; сохраняются aria-label навигации и focus-visible. Контейнер заменяется вместе с nav и правильными серверными ссылками, но без перехвата навигации, history API или ARIA tab widget. Уход со страницы завершает текущий жизненный цикл; автоPOST и фоновый retry не вводятся.

## Совместимость страниц и владение

Новый цикл ограничен POST-формой страницы курса. PATCH на `assignment.html` сохраняет reload текущего URL, включая completion. DELETE сохраняет confirm и переход по data-course-url. Чек-лист/repository не переписываются.

UI доставляет course.html-маркеры, сообщения, JS/CSS и browser-проверки. Логика доставляет окончательный результат, нормализацию режима/return context, одну локальную дату, no-store и публичный источник даты для проверок. Серверных дополнений к предложению 0.1 не требуется. HTTP/HTML-тесты маркеров выполняются после интеграции реального UI-шаблона; альтернативный test-only шаблон или endpoint не создаётся.
