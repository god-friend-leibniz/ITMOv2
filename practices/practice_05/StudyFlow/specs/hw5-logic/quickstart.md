# Phase 1: руководство проверки после реализации

Это план проверки, а не доказательство работы новой функции. Сейчас код и тесты не изменяются. HTTP/HTML-проверки принадлежат логике; интерактивные проверки ниже выполняются UI после доставки реального шаблона и объединения изменений. [Технический интерфейс 0.1](contracts/technical-interface.md) и распределение файлов уже приняты пользователем; по его сообщению UI подтвердил совместимость.

## Предварительные условия

Работать из StudyFlow на Python 3.12 с существующим lockfile, uv и установленным браузером. Подготовка и финальные gates — по корневому `AGENTS.md`; реальные credentials не требуются. Не загружать `.env` и не использовать пользовательскую базу для опытов с ошибками.

```sh
uv sync --frozen
uv run pytest -q tests/test_assignment_filtering.py tests/test_assignments.py tests/test_tasks.py
```

Если uv не в PATH, использовать `.tools/bin/uv`, когда он установлен, с локальными `UV_CACHE_DIR`/`UV_PYTHON_INSTALL_DIR` по AGENTS.md. Тесты создают временные SQLite-базы. На этапе реализации новые тесты добавляются по одному в цикле red → minimal implementation → green; существующий HTTP/HTML seam уже указан пользователем.

## Изолированный ручной запуск

Для ручной проверки после объединения с UI выделить отдельный временный каталог. Startup применяет миграции к новой базе, пользовательские данные не сбрасываются:

```sh
STUDYFLOW_DEMO_DIR=$(mktemp -d /tmp/studyflow-hw5-logic.XXXXXX)
STUDYFLOW_DB_PATH="$STUDYFLOW_DEMO_DIR/coursework.sqlite3" uv run uvicorn studyflow.web:create_app --factory --host 127.0.0.1 --port 8000
```

Не запускать параллельно другой сервер на том же порту. Фиксированную дату и переход через полночь проверять HTTP-тестом с `local_date_provider`, а не менять системные часы компьютера.

## Серверные сценарии

| Проверка | Ожидаемый результат |
| --- | --- |
| Набор A из spec.md при 2026-10-25 | all: 30,10,20,40,50,60,70; incomplete: 10,20,40,50,60; completed: 30,70; overdue: 10,20. В HTTP-fixture используются реальные ID из POST и заранее заданный ожидаемый порядок, а не подмена ID или копирование алгоритма сортировки. |
| Режим отсутствует/пуст/неизвестен | HTML курса и деталей нормализует в all. Несуществующий ресурс остаётся 404. |
| Пустой курс / нет совпадений | Успешный HTML и has_assignments=false / true соответственно, с прежними разными пустыми текстами. |
| Дата D → D+1 | Тот же app, новый GET использует новую дату; каждый результат использует одну дату. |
| Форма открыта D, POST D, GET D+1 | Задание с дедлайном D и пустым чек-листом входит в overdue по дате чтения. POST не определяет членство. |
| Задачи завершены/открыты/добавлены/удалены, дедлайн изменён/снят | Следующий GET отражает сохранённое состояние и правильную позицию; пустой чек-лист снова незавершён. |
| POST успешен, затем реальная блокировка временной БД и GET | GET возвращает существующую 503; после освобождения блокировки повтор только GET успешен, прежний ID присутствует один раз. |
| Неожиданный отказ чтения временной БД | Безопасная 500 без SQL/traceback; после восстановления чтение не создаёт и не откатывает задание. Не портить пользовательские данные; не подменять домен/persistence mocks. |
| JSON до/после HTML, с completion и без | Прежний полный список по ID, прежние поля/ошибки. `Cache-Control: no-store` проверяется для HTML курса; JSON headers не расширяются. |
| Детали с completion=overdue | `Back to course` и существующий `data-course-url` указывают на фактический курс с overdue; доступ к деталям не ограничивается фильтром. |

## Интеграция с UI

После появления реальных маркеров проверить обычный HTML GET: ровно один `#course-assignment-list`, верные data-course-id/data-completion/data-has-assignments, карточки с data-assignment-id в серверном порядке, формы вне контейнера. Затем UI подтверждает в браузере:

- После каждого успешного создания происходит свежее чтение, секция заменяется без собственного отбора/сортировки и без перезапуска JS из загруженного документа.
- Скрытость определяется созданным ID только после успешного чтения; первый скрытый результат имеет has_assignments=true.
- Ошибка GET/сети/неверного HTML после POST оставляет «Задание сохранено, но список обновить не удалось», неактуальный прежний результат и «Обновить список».
- Неудачный и успешный повторы обновления отправляют только GET, сохраняют один созданный ID и имеют защиту от повторного чтения во время ожидания.
- Режим сохраняется при переходах, изменении задач, возврате и удалении; сообщения доступны с клавиатуры/вспомогательным технологиям, сохранённое название выводится текстом.

## Полный gate

```sh
python3 scripts/verify_before_finish.py
```

Проверить feedback, а не только exit code обработчика: offline pytest, browser pytest и build должны иметь exit 0. При необходимости установленного Chrome/другого канала следовать AGENTS.md. Browser-тесты выполняются как общий gate, но новые сценарии UI реализует другая команда. Ни прохождение нынешних тестов на этапе plan, ни отсутствие маркеров до работы UI не доказывают готовность новой функции.
