## Входные данные

| Вход | Правило |
| --- | --- |
| ID курса | Существующий идентификатор курса; задаёт область списка. Другие курсы исключены. |
| `completion` | `all`, `incomplete`, `completed`, `overdue`. Отсутствующее, пустое или неизвестное значение сервер нормализует в `all`. Дополнительный выбор сортировки не требуется. |
| Сохранённые данные | Задания курса с существующими полями, необязательным дедлайном и производными счётчиками задач. Несохранённые значения формы не участвуют в списке. |
| Локальная дата | Получается сервером из окружения компьютера с StudyFlow заново для каждого результата; одна дата применяется ко всему результату. Браузер не передаёт дату/часовой пояс или признаки завершённости/просрочки как источник истины. |
| Контекст после записи | Подтверждённый прежним ответом создания ID и сохранённое название, текущий курс и режим. ID позволяет установить наличие задания в свежем серверном списке; дата и прогресс из ответа создания не заменяют этот список. |

Контекст `completion` переносится из курса в детали и обратно, включая сохранение деталей и успешное удаление. В деталях режим — только контекст возврата, не ограничение доступа; курс возврата определяется принадлежностью задания.

## Успешный результат чтения

Сервер формирует единый согласованный результат:

| Часть результата | Значение |
| --- | --- |
| Курс | Существующий курс, соответствующий входному ID. |
| Нормализованный режим | Одно из четырёх допустимых значений `completion`. |
| Окончательный список | Только задания курса, отобранные для режима и упорядоченные по правилу ниже; без дубликатов. UI не повторяет сортировку/фильтрацию. |
| Данные задания | Прежние ID, принадлежность курсу, название, описание, дедлайн или отсутствие даты, repository reference, прогресс `completed`, `total`, `percent`. Поля не получают нового смысла. Для карточек используются существующие данные. |
| `has_assignments` | Логическое значение наличия хотя бы одного задания в курсе **до фильтрации**, независимо от режима. |

Состав: `all` — все задания курса; `completed` — только непустой чек-лист со всеми выполненными задачами; `incomplete` — остальные, включая пустой чек-лист. `overdue` — незавершённые с дедлайном строго раньше опорной локальной даты. Сегодняшние, будущие, завершённые и без даты исключены из `overdue`; просроченные остаются в `all` и `incomplete`.

Порядок во всех режимах: дедлайн по возрастанию; задания без даты после всех датированных; равные даты и отсутствие дат разрешаются числовым ID по возрастанию. Имена и процент не являются ключами сортировки. Прогресс вычисляется по прежним правилам; пустой чек-лист — `0 / 0`, `0%`, `No tasks`. Отбор и показанный прогресс используют одни и те же значения счётчиков в рамках результата.

Пустой список и `has_assignments=false` означают `No assignments yet.`. Пустой список и `has_assignments=true` означают `No assignments match this filter.`. Непустой список подразумевает `has_assignments=true`. Навигация и существующие формы доступны при обоих пустых успешных результатах.

## Создание: два различимых результата

1. UI отправляет обычное создание по прежнему JSON-контракту. Во время записи блокирует повторную отправку и скрывает прежнее подтверждение. Ответ создания подтверждает запись, но не видимость в выбранном режиме.
2. После подтверждённой успешной записи UI сохраняет текущий режим, очищает форму и получает свежий серверный результат списка **после записи**, даже если по прежней дате/режиму видимость казалась очевидной. Пока чтение выполняется, видна обратная связь об обновлении; окончательная видимость ещё не объявляется.
3. При успешном чтении UI отображает полученный список, нормализованный режим и пустое состояние по `has_assignments`. Если сохранённый ID присутствует, задание показано на серверной позиции. Если отсутствует, UI подтверждает создание с сохранённым названием, пояснением «скрыто текущим фильтром» и ссылкой «Все» того же курса. Браузер не делает собственный вывод о просроченности.
4. При отказе чтения подтверждение записи остаётся действительным. UI показывает **«Задание сохранено, но список обновить не удалось»**, действие **«Обновить список»** и сохраняет курс/режим. Прежний список, включая прежнее пустое состояние, явно обозначен как неактуальный; отсутствие нового задания не трактуется как его скрытость или неудача записи.
5. «Обновить список» повторяет **только чтение** текущего курса/режима. Оно не отправляет создание повторно, не восстанавливает уже сохранённую форму для автоматической отправки и не откатывает запись. Пока чтение ожидает результата, его повторный запуск блокируется. Успех заменяет неактуальное представление и показывает соответствующую видимость сохранённого ID; отказ оставляет сообщение и возможность повторить чтение.

Подтверждение скрытого создания не требует таймера или хранения между страницами; исчезает при следующей отправке, переходе или перезагрузке. Ошибка обновления сохраняется до успешного обновления или ухода со страницы. Все сообщения доступны вспомогательным технологиям; названия отображаются как обычный текст. Текст нового сообщения задан пользователем; существующие подписи интерфейса и JSON-сообщения не локализуются попутно.

## Ошибки

| Исход | Обязательный результат на границе и поведение UI |
| --- | --- |
| Курс не существует | Существующая ошибка 404; не успешный пустой курс. Сохраняется понятная обратная связь об отсутствующем ресурсе. |
| Хранилище занято при чтении | Существующая 503 `DATABASE_BUSY` с безопасным сообщением; не отсутствие совпадений. |
| Неожиданный отказ чтения | Существующая 500 `INTERNAL_ERROR`; не пустой успех, без SQL, traceback и секретов. |
| Подтверждённый отказ записи | Прежняя ошибка валидации/сервера; ввод и режим сохраняются, доступно исправление и повтор создания, подтверждение успеха отсутствует. |
| Сетевая ошибка записи без подтверждённого исхода | UI показывает прежнюю сетевую ошибку, сохраняет ввод/режим, не утверждает успех или гарантированное отсутствие записи и не повторяет запись автоматически. Новый протокол идемпотентности не вводится. |
| Запись подтверждена, чтение/его доставка неуспешны | Отдельное UI-состояние «Задание сохранено, но список обновить не удалось» с повтором только чтения; исходный результат записи не превращается в ошибку создания. Не вводится новый код JSON API. |

Недоступность GitHub/MCP не влияет на эти операции. Чтение не изменяет coursework; обработка ошибки обновления не инициирует повтор записи. Для успешного пустого результата сообщение об ошибке не показывается.

## Актуальность и проверочные примеры

- Каждый серверный результат заново учитывает сохранённые дедлайны/счётчики и одну актуальную локальную дату. Дата старта приложения, открытия формы, браузера или UTC-дата её не заменяют. Дедлайн остаётся календарной датой без времени/зоны; просроченность и дата результата не сохраняются как coursework и не добавляются в публичный JSON-ресурс.
- Открытая страница сама не обязана меняться после полуночи или изменений в другом окне. При следующем запросе, переключении вкладки, возврате/перезагрузке или повторе чтения действует новый серверный результат. Фоновый опрос и таймер не требуются.
- **Полночь при создании**: форма `overdue` открыта 2026-10-25 в 23:59, дедлайн 2026-10-25. Запись подтверждена и свежий список сформирован 2026-10-26 в 00:01: новое задание с пустым чек-листом присутствует. UI не показывает «скрыто фильтром», даже если браузер считает, что ещё 25-е. Если дата сменилась между записью и чтением, решает дата нового результата чтения.
- **Отказ чтения после записи**: создано ровно одно задание; запись подтверждена, последующее чтение отказало. UI сообщает о сохранении и неудачном обновлении. Два повтора чтения (первый неуспешный, второй успешный) не создают новых заданий; итоговый список соответствует последнему успешному серверному результату. Промежуточный отказ не объявляет задание скрытым.
- **Без смены даты**: 2026-10-25 новое задание с дедлайном 2026-10-24 входит в `overdue`, с 2026-10-25, 2026-10-26 или без даты — отсутствует. В каждом случае UI подтверждает эту видимость по свежему результату, не по условию в браузере.

## Обязанности сторон

| Сторона | Ответственность |
| --- | --- |
| Логика / сервер | Нормализация режима; область курса; текущая локальная дата; окончательный состав/порядок; согласованные прогресс и `has_assignments` до фильтрации; свежий результат после записи; прежние категории ошибок и сохранность данных/JSON-контракта. Внутренние алгоритмы этим контрактом не задаются. |
| UI | Отправить курс/режим; отобразить серверный результат; сохранить текущий выбор и возврат; использовать ID для проверки наличия созданного задания; различать запись, обновление, пустой результат и ошибку; повторять только чтение при отказе после записи; сохранить клавиатурную доступность, сообщения, формы и безопасный текст. Просроченность и дату браузер не вычисляет. |
| Контроль соответствия до реализации | Поддерживать соответствие документации обеих сторон этому контракту и примерам полуночи/отказа чтения, сохраняя JSON API. Общая формулировка принята пользователем; выбор технического механизма относится к plan и сейчас не выполняется. |

JSON API сохраняет прежние маршруты, поля, статусы/валидацию и форму ошибок, полный нефильтрованный список курса в порядке ID. Параметры HTML-режима не включают в нём сортировку по дедлайну или фильтрацию. Владение, каскады, прогресс и GitHub-сценарии сохраняются.
