# Phase 1: данные серверного результата курса

Дата: 2026-10-25. Основание — [spec.md](spec.md) и [общий контракт 1.0](contracts/course-list.md). Это описание существующих данных и вычисляемого представления; новых таблиц, моделей ORM или иерархии DTO нет.

## Сохраняемые сущности

| Сущность | Данные, нужные изменению | Связи и ограничения |
| --- | --- | --- |
| Course | `id`, прежние название и описание | Владеет заданиями; отсутствующий курс — существующая ошибка 404. |
| Assignment | `id`, `course_id`, `title`, `description`, `due_date`, `repository` в существующем результате use case | Принадлежит одному курсу; ID/родитель неизменяемы. Дедлайн — null либо реальный канонический `YYYY-MM-DD`. |
| Task | `assignment_id`, `is_completed`; остальные поля сохраняются | Принадлежит одному заданию; completion — strict boolean. Источник текущих счётчиков. |

Схема SQLite, миграции, валидация записей, каскады и ссылки на репозитории не меняются. `coursework.list_assignments` возвращает прежние поля с прогрессом; исходный SQL-порядок ID сохраняется для JSON API.

## Вычисляемые значения

| Значение | Тип и источник | Правило |
| --- | --- | --- |
| `progress` | Существующий dict: integer `completed`, `total`, `percent` | Счётчики одного чтения заданий; `floor(100 * completed / total)`, при total=0 — 0. Не сохраняется. |
| Завершённость | Локальный boolean правила отбора | `total > 0 and completed == total`. Пустой, не начатый и частичный чек-лист незавершены. |
| `today` | Один объект `datetime.date` от `local_date_provider()` на результат курса | Локальная дата компьютера с StudyFlow на момент формирования результата; не дата формы, POST, UTC или браузера. Не сохраняется и не передаётся UI для расчёта. |
| `completion` | Нормализованная строка | all/incomplete/completed/overdue; любое другое, пустое или отсутствующее значение → all. Не статус задания. |
| `has_assignments` | boolean от полного списка данного курса | Вычисляется до отбора из того же списка, который используется для проекции. |
| `assignments` для HTML | Новый упорядоченный список прежних dict задания | Состав зависит от режима; сортировка по дате, отсутствию даты, ID. Исходный список/поля не меняются. |

Контекст обычного `TemplateResponse`: `course`, `assignments`, `completion`, `has_assignments`. Это прежние ключи, не новая JSON-схема. Принятое HTML-представление атрибутов описано в [technical-interface.md](contracts/technical-interface.md).

## Переходы результата

- Успешная запись нового задания создаёт пустой чек-лист. Видимость определяется последующим результатом по его дате и режиму, не ответом POST самостоятельно.
- Завершение/повторное открытие, добавление/удаление задач и изменение/снятие даты меняют следующий результат без обновления сохраняемого статуса.
- Полночь или смена локальной зоны меняют опорную дату следующего результата в том же процессе. Внутри результата дата фиксирована для всех элементов.
- При подтверждённой записи и ошибке GET задание сохраняется. «Сохранено» и «список не обновлён» — состояния взаимодействия UI; не новые состояния Assignment. Повтор GET ничего не записывает.
- Успешный пустой результат различается по has_assignments; ошибка чтения не создаёт успешного результата или фиктивного пустого курса.

Новые идентификаторы результата, даты в базе, признаки overdue/completed у Assignment, сохраняемая выбранная вкладка и repository summary не добавляются.
