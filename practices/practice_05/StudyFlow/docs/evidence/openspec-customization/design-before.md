# Design

## Context

Пользователь расширил исходную сортировку отдельной вкладкой «Просроченные» и выбрал локальную дату компьютера с StudyFlow. Пять условий приёмки — в [proposal.md](proposal.md), наблюдаемые сценарии — в [delta spec](specs/course-assignment-filtering/spec.md).

Сейчас `db.list_assignments` выполняет `ORDER BY id`, общий `coursework.list_assignments` добавляет прогресс и обслуживает HTML/JSON. `web.course_detail` нормализует три значения `completion`, запоминает наличие заданий до отбора и фильтрует по счётчикам чек-листа. `assignment_detail` отдельно нормализует тот же параметр и строит возврат в фактический курс задания. Шаблон последовательно выводит готовый список; создание в All/Incomplete вызывает reload, в Completed оставляет фильтр и показывает подтверждение скрытого создания.

Дедлайн уже хранится как `null` или валидная календарная строка `YYYY-MM-DD`; прошлые даты разрешены, PATCH принимает `null` для очистки. Часы и часовые пояса сейчас для фильтра не нужны; источника даты в app factory пока нет. Два требования main spec явно обещают HTML-порядок по ID. Delta заменяет эти полные блоки; пять остальных прежних требований остаются действующими. Новые правила расширяют существующую capability, не дублируют её.

## Goals / Non-Goals

**Goals:** четыре вкладки, единая сортировка внутри каждой, строгое определение локального дня, непрерывность URL и корректное создание в Overdue без изменений JSON API.

**Non-Goals:** сохраняемый статус просроченности, настройки часовых поясов, время дедлайна, таймер в полночь, настройка сортировки, второй фильтр, изменение SQL/API, пагинация, инфраструктура или миграции.

## Decisions

### 1. Термин и правило принадлежности

Предлагаемое дополнение `GLOSSARY.md` при apply: **Overdue assignment** — незавершённое по чек-листу задание с дедлайном раньше сегодняшней локальной календарной даты. Это не новый жизненный цикл, не факт сдачи и не оценка. Термин зафиксирован здесь до реализации; общий glossary в planning не меняется. Отдельный ADR не нужен: правило отображения обратимо и не меняет архитектуру хранения.

Пусть `C = total > 0 and completed == total`, `D` — сохранённый дедлайн, `T` — локальная дата запроса.

| Вкладка | Значение completion | Предикат |
| --- | --- | --- |
| Все / All | all, отсутствие, неизвестное или пустое | все задания текущего курса |
| Незавершённые / Incomplete | incomplete | `not C` |
| Завершённые / Completed | completed | `C` |
| Просроченные / Overdue | overdue | `not C and D is not None and D < T` |

Пустой чек-лист незавершён. Сегодняшняя дата ещё не просрочена; завершение исключает задание даже с прошлой датой. Просроченные остаются во «Все» и «Незавершённые». Не комбинировать `overdue` со вторым независимым режимом и не менять прогресс.

### 2. HTML-путь сначала отбирает, затем сортирует

```text
GET /courses/{id}?completion=...
  -> normalize completion (all / incomplete / completed / overdue)
  -> read course assignments with saved progress
  -> remember has_assignments before filtering
  -> capture server-local today once for this request
  -> filter by selected tab
  -> sort visible assignments by (due_date is None, due_date or "", id)
  -> render course.html with current tab and ready list

GET /api/courses/{id}/assignments
  -> existing coursework.list_assignments
  -> all assignments in ascending ID order, unchanged fields/errors
```

Ключ явно ставит отсутствие даты в конец и разрешает равенство через ID, в том числе среди недатированных. Канонические строки ISO сравнимы хронологически; пустая строка внутри ключа не становится допустимой датой ввода. Сам ключ не использует часы: во «Все» прошлые даты просто идут раньше будущих. У Overdue часы влияют на состав, а не на порядок.

Операции остаются в HTML-пути обычными функциями над уже прочитанным списком; не вводить сервисы, репозитории или новый SQL-режим. Сортировка после отбора стоит `O(k log k)` для видимых `k` записей. Общий use case и SQL сохраняют порядок по ID, иначе изменился бы JSON. Шаблон получает готовые данные; в Jinja и браузере нет второго алгоритма отбора/сортировки.

`has_assignments` сохраняется до отбора: пустой курс и непустой курс без просроченных остаются разными состояниями. Общие проверки 404 выполняются прежним путём, не превращаются в пустой результат.

### 3. Сегодня — локальный календарный день сервера

Production-источник — стандартная системная локальная дата (`date.today()`), без UTC-преобразования, фиксации зоны или чтения даты браузера. Получать дату один раз внутри запроса курса, а не при создании приложения, модуля или на каждую строку. Дата дедлайна остаётся календарной датой, не timestamp; сравнение строгое `<`, без вычитания 24 часов.

Для детерминированных публичных проверок добавить в `create_app` небольшую внешнюю границу даты: необязательный callable `today_reader`, возвращающий локальную `date`, с production default `date.today`. Это аналогичное существующему `summary_reader` средство подстановки внешнего источника, без clock-классов и параметров в HTTP/JSON. Тесты управляют датой через app factory, используют настоящую временную SQLite и публичные запросы, не подменяют домен или SQL.

В одном работающем экземпляре приложения два запроса по разные стороны локальной полуночи получают разные дни. Месяц, год и високосный день обрабатываются сравнением календарных дат. Если локальный день не совпадает с UTC/браузером, побеждает серверный. Зона — системная зона процесса; `UTC+03` в сценарии только пример. Смена системной зоны отразится при следующем чтении; пользовательских настроек не добавлять.

Открытый HTML — снимок ответа: автоматического обновления в полночь нет. Следующий GET, в том числе возврат из задания, определяет новый день. Дедлайн не сравнивается с часами страницы, сохранённой при старте датой или часами браузера.

### 4. Вкладка — существующий контекст URL

Признать `overdue` в обоих HTML-маршрутах: курса и задания. Добавить четвёртую обычную ссылку в существующую навигацию с обозначением текущей вкладки и клавиатурной доступностью; английская подпись `Overdue` соответствует текущему языку интерфейса. Не вводить SPA tabs или новое состояние в браузерном хранилище. Общая нормализация может быть небольшой обычной функцией, без общего механизма фильтров.

| Действие | Результат |
| --- | --- |
| Переключение вкладки, reload, открытие URL | Новый GET с тем же completion; отбор и сортировка на сервере |
| Переход в задание и Back | Контекст completion передаётся как сейчас; возврат в фактический курс задания |
| Завершение/повторное открытие/добавление/удаление пунктов | Следующий GET заново вычисляет C и членство Overdue |
| Изменение дедлайна на другой прошлый | В Overdue новое место по дате и ID |
| Изменение дедлайна на сегодня/будущее либо очистка | В Overdue задание исчезает, вкладка остаётся; в прежних вкладках отбор по C прежний, порядок обновлён |
| Удаление задания | Возврат с тем же completion; удалённого задания нет, остальные отсортированы |
| Неизвестный/пустой completion, прямой вход в задание | Прежний нормализованный All, прежние 404 |

### 5. Создание в Overdue получает свежий серверный список

Новое задание имеет пустой чек-лист, поэтому под Overdue его видимость зависит от даты нового чтения. Сравнение с `today` из исходного HTML ошибочно, если форма открыта до полуночи, а создание завершилось после неё. Браузерный `new Date()` может расходиться с согласованным источником.

Минимальный выбранный поток для Overdue:

1. Отправить существующий POST с прежним JSON. До успешного ответа действуют прежние pending/ошибки и защита повторной отправки.
2. После подтверждения сохранения выполнить свежий GET **существующей HTML-страницы курса** с тем же `completion=overdue`, без использования кэшированного ответа. Это единственный расчёт нового состава и порядка.
3. Из полученного HTML заменить только серверный участок списка (заголовок/навигация/карточки/пустое состояние), сохранив живую форму и её status. Для участка допустим один явный DOM-id; карточке — идентификатор задания. Не заменять всю страницу, не исполнять скрипты из ответа, не строить карточки из JSON в браузере.
4. Если сохранённое задание присутствует в свежем участке, показать его обычной карточкой. Если отсутствует — использовать прежнее доступное подтверждение: название через `textContent`, объяснение скрытия и ссылку All. Сбросить успешную форму, сохранить выбранный фильтр/URL и корректное пустое состояние.

Это один дополнительный HTML GET для нового режима, без нового API, query-параметра для flash, browser storage и дублирования предиката даты. `All/Incomplete` сохраняют прежний reload, `Completed` — прежнее подтверждение без reload; менять их поток не требуется. Ссылка All в любом подтверждении читает полный отсортированный список.

Сохранение POST и обновление списка — разные результаты: если POST успешен, а GET/разбор HTML не удался, не выдавать общую ошибку «не удалось сохранить» и не предлагать повторить POST. Показать подтверждение сохранения с предложением обновить текущую вкладку, не утверждая неподтверждённое скрытие. Сбросить успешно сохранённую форму. Новая отправка убирает старый status как сейчас. Дополнительного автоматического POST или фонового retry нет.

Ответ GET остаётся снимком своего локального дня: если полночь наступила после этого ответа, актуализация произойдёт при следующем GET, как и при обычном открытии. Внутри одного ответа дата не меняется между строками.

## Risks / Trade-offs

- Дополнительный HTML GET после создания под Overdue усложняет этот поток, но сохраняет единый источник даты/отбора и не меняет API. Ограничить замену одним серверным участком; не превращать это в общий механизм частичных страниц.
- Старый HTML-порядок по ID обещан в двух местах main spec и в `StudyFlow/spec.md`: delta заменяет полные блоки с сохранением прежних сценариев, локальную spec обновить вместе с реализацией.
- Сортировка только по дате может скрыто полагаться на стабильность SQL: ID должен быть явным последним ключом, включая несколько null.
- Today, вычисленный при старте, даёт устаревшую вкладку после полуночи: тестировать смену даты на одном экземпляре приложения без перезапуска.
- Локальная зона сервера может отличаться от браузера: это согласованная семантика, а не повод добавить пользовательские зоны или timestamp.
- Стоимость чтения всех заданий остаётся прежней; SQL-оптимизация и пагинация не входят в задачу.

## Verification

Существующий `tests/test_assignment_filtering.py` уже проверяет изоляцию курса, нормализацию, чек-листы, пустые состояния и JSON. Его fixture без дат остаётся полезной регрессией прежнего ID-порядка при равенстве ключа. Добавить отдельный перемешанный набор дат из delta с буквальными ожидаемыми ID, не вычислять ожидаемое тем же ключом, что production. Проверять API на том же наборе: порядок дат намеренно отличается от ID.

Публичные HTTP/HTML-проверки: четыре режима, вчера/сегодня/завтра/null, полные/частичные/пустые чек-листы, смена даты на одном app, календарные границы, локальная дата при расхождении с UTC/браузером, нормализация и 404, возврат и изменения сохранённых данных. Использовать часы как внешнюю границу, без sleep и реального ожидания полуночи. Граница `today_reader` — узкое дополнение к уже согласованным HTTP/HTML и browser seams.

Браузерные проверки: клавиатура, выбор/reload/detail/back/delete, изменение и очистка даты, создание видимого/скрытого в Overdue, первое скрытое создание, pending/ошибка/повторная попытка и очистка status, создание через смену дня без перезапуска сервера, успешный POST с неуспешным HTML refresh, All-ссылка и регрессия прежних режимов. Реальные страницы и SQLite; сетевой сбой моделировать на внешней browser/HTTP-границе, не во внутренних функциях.

Работать вертикально по TDD: один наблюдаемый провал → минимальное поведение → зелёная проверка, с относящейся к срезу документацией. После реализации выполнить fast-handler при недоступном автоматическом dispatch и штатный `python3 scripts/verify_before_finish.py`: основные тесты, browser и build; смотреть содержимое JSON, а не только exit handler. Предыдущие 232/66 тестов — исторический результат прошлого change, не проверка этого проекта документов или будущего поведения.

## Migration Plan

Миграций данных и зависимостей нет. Изменяются HTML-адаптер, шаблон, узкая ветка создания, публичные тесты и локальная документация. `GLOSSARY.md` получает только определение термина; `StudyFlow/spec.md` — поведение страницы и источник даты. Main spec синхронизируется отдельным разрешённым workflow после принятия реализации.

Откат убирает вкладку, локальную дату и HTML-сортировку; данные и JSON не требуют преобразования. Planning не меняет приложение, тесты, общий glossary или main spec.

## Open Questions

Нет блокирующих продуктовых вопросов. Источник даты согласован: локальная дата компьютера с веб-сервером. Отсутствие midnight timer и узкий HTML refresh после создания — явно описанные решения этого предложения для review.
