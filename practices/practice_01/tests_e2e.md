# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный | Сервис доступен по HTTP; известен URL endpoint /api/reviews; при необходимости настроен LLM-заглушка | Отправить POST /api/reviews с JSON {"diff": "<строковый diff PR>"} | Получен JSON-ответ, содержащий ключ "comment" со строковым значением; инженер просматривает черновик и сам принимает решение по PR | Проверить тело ответа на наличие строкового "comment"; вручную подтвердить, что решение по PR принято человеком вне сервиса |
| Негативный (нет ключа diff) | Сервис доступен по HTTP | Отправить POST /api/reviews с пустым JSON {} | Получена контролируемая диагностируемая ошибка об отсутствующем `diff`; ключ `comment` отсутствует | Проверить диагностическое указание отсутствующего `diff` и отсутствие `comment`; не требовать конкретного статуса |
| Граничный (пустой diff) | Сервис доступен по HTTP; LLM-заглушка возвращает `EMPTY_DRAFT`. | Отправить POST /api/reviews с JSON {"diff": ""}. | Получен JSON с `{"comment": "EMPTY_DRAFT"}`. | Проверить тело ответа и равенство значения `comment` ответу заглушки. |

## Как использовали AI

- Строка в [`prompts.md`](prompts.md): P1-06.
- Что проверил студент и какие исправления поручил агенту: позитивный, негативный и граничный сценарии имеют наблюдаемые результаты; финальное решение по PR остаётся за человеком.
